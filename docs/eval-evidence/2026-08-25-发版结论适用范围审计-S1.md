## 一、确证事实
1. **夹具只有 `stage`/`company`/`ev`(时间线)**；`claims`/`action_items`/`deadlines` 建档函数**不存在、使用次数 0** → **每个剧本第 1 轮 S1 必空**（构造性结论，不依赖抽样）。

3. 产线 `citation-block.ts:308` `if (out.size > 0) return out; // S1 恒优先` → S1 非空时 S2/S3/S4 不执行。
4. **S1 三来源均真实存在**（① `claims.basis` ② 行动卡 `detail` 里的条号 ③ `deadlines.derived_from`），**无幻影字段**（我核过 migrate.ts：action_items 无 basis 列，但 S1 ② 读的是 detail 文本，实现自洽）。
5. **评测装置在轮间共享同一 db/caseId**（`scripts/eval-agent.ts` 建库一次、turn 循环内复用，且逐轮比对 `MAX(id) FROM action_items`）→ **档案在轮与轮之间确实累积**，深会话剧本可自然长出 S1（无需预置）。

## 三、不能确证、须明说的两处
1. **3 个 2 轮剧本（S02/S08/S15）的第 2 轮 S1 是否非空**：轮间档案确实累积（见 §一.5），若第 1 轮写入的行动卡 detail 含条号，第 2 轮 S1 即非空——**但我无法从现有证据判定**，因为**⭐ 块属注入产物、不进转录**（已在迭代清单上的可观测性缺口）。所以：**S1 是否曾偶然被触发过，目前无法从产物回答**——这本身就是该加注的事实。
2. 承上：**"⭐ 从未渲染"这句话我不能说**。我扫过全部证据文件"本轮核心依据条"命中 0，但**转录本就不含系统提示词**，这个 0 是**观测不到**而非**没发生**（差点把它当结论，按"零结果需自证"拦下）。

## 四、给深会话剧本的硬约束（由本审计推出）
- 前 2–3 轮必须**真实触发** claim_calc / 行动卡 / 期限推算并落库，且**建档段本身要有断言**（断言 claims/action_items/deadlines 实际行数 > 0），否则观察窗测的仍是空档案分支而我们会以为测的是 S1。
- **自然积累路径本身是被测对象**（charter §9 要求 agent 把事实落进结构化字段），故**优先自然积累、不用夹具预置**；确需预置时必须标注"预置≠自然积累"。
- **S1 自我强化循环**（manager 指出）须专门设计：前几轮故意写入**一条存疑/错误的依据**，观察后续轮是否将其当核心条反复强化——**错误在档案里不衰减、会自我复制**，这是 S1 分支特有的风险，S2/S3/S4 没有。
