# 「引判例必带案号」断言 · 评测面意见（评测官 → ws2 会签 → manager）

| 项 | 数 | 说明 |
|---|---|---|

## 二、核心意见：ws2 的两态设计会重犯缺陷⑨（派人去补不存在的东西）
ws2 初判：`卡有案号未引=FAIL / 卡无案号=pending 派 WS4`。**问题在第二支**：46 张卡的 case_no 写着「官方案例，未公开案号」——**这不是缺料，是事实本身**（典型案例发布时就不带案号）。判 pending 派 WS4，等于**派人去补录一个客观不存在的案号**，与 §46 那次「派外勤补库里已有的卡」同形（缺陷⑨：逻辑越权，把"查不到"当成"不存在"；这里是把"不存在"当成"没录"）。**必须三分而非两分**：
| 卡侧状态 | 判定 | 账记 |
|---|---|---|
| ① 有可解析案号，回复未引 | **FAIL** | 模型（真挂） |
| ② 卡**明示**无公开案号（`未公开案号` 等标记） | **豁免/N-A** | 谁都不记——**要求回复给"出处+案例序号"**（如「三中院 2025 典型案例·案例五」）即达标 |
| ③ 字段空/不可解析 | **pending** 派 WS4 补录 | 知识库 |
**②必须单列**，否则 46/93 涌进 WS4 队列全是补不出来的活——「长期红灯训练所有人无视红灯」（你们 README 原话）。

## 三、另四条评测面要件
1. **格式校验器先行**：18 张"有案号"全部混着法院名/日期，**字段非空 ≠ 可引用**。断言必须用 `（YYYY）…号` 正则判可解析，否则会拿"填了垃圾"的卡去罚模型（模型根本引不出一个规范案号）。**建议 WS4 字段拆分（court/judged_at/case_no 归位）先落，断言后上**——否则断言首日就是一片假 FAIL。
2. **比对面同源**：断言读的 case_no 必须与产线判例渲染取值走**同一函数**（同源公理；缺陷⑤第二半刚栽在"两边各取各的语料"）。
3. **位置口径沿用 §八**：判例作为**行动卡依据/结论句依据**=核心位，必须带案号（或②的出处+序号）；背景顺带一提=辅助位，给来源卡即可。不分位置会重演 G4 从严那几天的返工。
4. **不裸上 L1，四态式落地**——与 ws2 一致。理由补强：case_no 空/不可解析时若判 FAIL，最省力满足方式是**编一个案号**，而零编造是 L1（第五闸刚为此立起来）；**断言不得把模型逼向更重的违规**（A 系「它会不会激励模型用错误方式满足它」）。

## 四、结论
方向赞成，**条件是**：三分（含"明示无公开案号"豁免）＋格式校验器＋字段拆分先行＋位置口径＋同源比对面。以上齐备再上线，否则这条断言的首批产出会同时污染 WS4 队列与成绩单。
