## 四、断代之后仍未闭合的两处（验收发现，2026-08-26）

### ① `leverageTrail` 只读 `t.events`，读不到转录里新落的 `turns[].leverage`

`58d4e26` 把 `leverage: { outcome, stripped, bodyRaw }` 落进了 `ScenarioEvidence.turns`（`report.ts:50`），
但 `assertions.ts` 的 `leverageTrail(t)` 取的是 `t.events`，而 `TurnRecord` **没有** `leverage` 字段。

后果分两种跑法：
- **实时跑批**：`t.events` 在内存里，判据拿得到 → 正常。
- **离线回放归档 JSON**：`events` 不进归档（`report.ts` 的 turn 形状里没有它），
  新落的 `leverage` 字段判据又不读 → `trail.fired` 恒为 `false` → **判成「闸未开火」并给 PASS**。

**也就是说：闸前正文已经落盘了，但判据回放时看不见它，会在正是这条 L1 要防的失败模式上给出假绿。**
且判据**分不清**「这份转录跑在旧代码上」与「闸确实没开火」——两者在 `t.events` 为空时长得一模一样。

修法（归后台技术，我不改产品/转录结构）：`TurnRecord` 加 `leverage?`，`leverageTrail` **先读 `t.leverage`、回退 `t.events`**；
并加一个**来源标记**（这份转录有没有 leverage 字段），缺失时判 `na`（无判别力）而不是 PASS。
