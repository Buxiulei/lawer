## 一、v1 的三处缺陷与 v2 的对应修法

| v1 缺陷 | 证据 | v2 修法 |
|---|---|---|
| 把**跨两层**的目标写成单层通过线 | 九对里 4 对是同义层（`被裁↔裁员` 不共享 2 字词缀），词缀改造**结构上够不着** | **分层判**：形变层与同义层各自计分 |
| 过宽绊线设在**均值**上，均值不灵敏 | 均值 5.78 未触发 6.0，而触顶条数 7→26 | 取消均值线 |
| **「触顶」本身也是被截断的读数** | `limit=8` 是天花板：`实质命中=8` 只表示"≥8"，真实是多少不可知 | **改用 `limit=218` 量真实广度** |

### 量具发现（本批实测，v2 的依据）
```
                limit=8 平均    **limit=218 平均**   中位     最大
基线 b07fee0       2.3              **10.4**        **1**     103
改造 01b3349       5.8              **47.5**       **25**     173
```
> **基线上一个 query 通常只实质命中 1 张卡；改造后是 25 张。**
> **`limit=8` 把这件事整个挡在天花板下面**——所以 v1 的均值与触顶都读不出它。

## 二、硬闸（任一触发即否决，不看其它任何数字）
```
① 四条绊线（sentinel-1/2、dust-1/3）实质命中必须全 0
② **真实广度绊线（新）**：用户侧 36 条在 limit=218 下的**实质命中中位数 ≤ 8**
   依据：若超过一屏（8 张）的卡全都算"实质命中"，这个标签就不再有区分力。
   基线中位 1、返工前 25 —— **这一条必须压回来**。
```

## 三、主判据：分层判
**「翻中」定义不变：`应召回 > 0`**（实质命中>0 而应召回=0 是"捞到了但不是要的"，不算修好）。

| 层 | 对数 | 用例 | 通过线 |
|---|---|---|---|
| **形变层** | 5 | `S12-t1` `rw-qianzi-1` `rw-misc-1` `rw-misc-2` `rw-misc-4` | **≥ 4/5 翻中** |
| **同义层** | 4 | `rw-caiyuan-1` `rw-peichang-1` `rw-peichang-2` `rw-cuiqian-1` | **本轮不判**（归缓议的 ③；本轮翻中算加分不算要求） |

**`rw-misc-2` 为本次必修项（manager 裁）**：「怀孕了公司把我调到外地」返工前捞回 8 张全不相干
（关联公司混同／注销破产／竞业举证）——**词缀放宽亲手造出的新尘埃**。
**该条不翻中即否决**，且**必须应召回 > 0**，不接受"实质命中变多"作为改善证据。

## ⚠️ 五、参数独立条款（manager 裁，新增）
> **任何常量不得对着验收线调参；取值必须由数据性质自证。**

本轮实例：`DOMAIN_MIN_DF=8` 经后台技术**主动坦白**，有一半原因是为了留在 v1 的 6.0 线以下。
**一个被调参对准的阈值，就不再是独立检验。**

v2 执行细则：
1. 改造方需在**常量注释里写明取值的数据依据**（如 DF 分布上的拐点），**不得以"落在验收线内"为理由**。
2. 我在判读时**逐个常量核一次它的依据是否成立**；若依据只有"落在线内"，**该常量按触发处理**（人工逐条核 ≥5 条样本）。
3. **坦白记功**：本轮正因他先说，那条线才从"静默通过"变成"人工复核"——**并因此查实了 `rw-misc-2` 这个过宽实例**。

## 六、报数强制（manager 裁：成对报数升为强制）
**任何一次报告必须同时给出这三个数**，缺一不受理：
```
应召回（多捞到了多少对的）
真实广度 limit=218 中位数（顺带捞进了多少不对的）
捞满捞错条数（实质命中>0 且 应召回=0）
```
> **只报应召回，等于只报捞对了多少、不报捞进了多少不对的。**

## 七、本批仍**不能**证明的
1. 不能证明产品变好——这把尺只量检索有没有把料递到 agent 手上。
2. 不能证明覆盖面足够——48 条不是用户真实提问分布的样本。
3. **同义层不在本轮判据内**——它翻中是好消息，不翻中不构成本轮的不通过。
