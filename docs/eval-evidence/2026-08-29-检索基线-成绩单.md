## ⚠️ 三、首跑先量出的是**这把尺自己的三处缺陷**（已修，显式披露）
1. `sentinel-1` 原句含「北京」⇒ 逐字命中带「北京」keyword 的卡、**实质命中 2**。去掉地名后 0。
2. `dust-2`「深圳住房公积金缴存比例」实质命中 2（「公积金」是领域词）⇒ **删除**。
3. `tw-qianzi` 原句「被要求签字的文件 应对」**两侧都不中**，而目标卡明明存在。
   实测：**只有逐个点名文件种类**（离职申请／协商解除协议／空白件／签字）才捞得到（8/8）。
   ⇒ **"泛称捞不到、点名才捞得到"本身就是匹配缺陷的一个实例。**

**这不是把尺调到好看**：预设读法**事前**就写了「孪生臂普遍不中 ⇒ 先修尺子」与「哨兵必须恒 0」，
上面三处正是在执行那两条。**改的是尺子，没有改判据，也没有改任何一条 `expect`。**

### 同批发现的一处矩阵逻辑错误（已改预设读法）
原写「两侧都不中 = 覆盖缺口」——**不成立**。地板守卫已保证每个 `expect` 的卡都真实存在，
所以两侧都不中**只可能是我这边的问题**（孪生句不够答案侧，或 expect 标错）。
**覆盖缺口要另设判据，不能从这一格读出来。**

## 四、本批**不能**证明的（预设读法原文）
1. 不能证明「改了就会好」——基线只描述现状。
2. **实质命中率不是产品质量指标**：它量的是**检索有没有把料递到 agent 手上**，不量 agent 拿到料之后用得对不对。**两件事，两把尺。**
3. `expect` 是我的判断：依据逐条写在 `why` 字段里，**写出来是为了让别人能反驳它**；被驳回则**改标注不改数字**。
4. 卡库固定在 218 张这一版。库变了，基线作废。
