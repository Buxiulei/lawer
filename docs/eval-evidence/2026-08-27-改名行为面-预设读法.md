## 三、**本批能证明什么、不能证明什么**（这一节是本文件的核心）

**能**：
1. 改名后 L1 五条与 G 系**是否仍然全过**——挂了就是发现，且是硬发现。
2. **自称有没有进入用户面正文**——这是个**可数量**，且改前有归档语料可比（见第四节）。

**不能**：
- **不能证明「改名对模型输出零影响」。** 两跑不足以刻画分布；模型输出本来就跑跑不同。
  **一切措辞差异都不可归因于改名**，除非它同时满足：改后两跑都出现、改前语料零出现。
- 因此本批的正向结论只能写成 **「未观察到影响」**，不能写成 **「无影响」**。
  ——**「没看见」与「不存在」是两件事**；两跑这个样本量只够支持前者。

**判准**：模型自称不该出现在下发给用户的正文里（它是 system prompt 的身份设定，不是话术）。

- **改后**：本批两跑的 `t.text` 里数「土拨鼠劳动仲裁」「裁员应对专员」各几次。

- **若改前就 >0** ⇒ 那是一条与改名无关的既有问题，单独报，不算在改名账上。

## 七、第二批（`土八鼠`）**不是"同一个改动再跑一遍"**（2026-08-28，跑之前补）

后台技术提醒的一点成立，我把它写进读法：
**`土拨鼠劳动仲裁` → `土八鼠` 不只是换个字，它去掉了「劳动」「仲裁」两个词，
而这两个词在出站敏感词清单里**（`notify/copy.ts:25` 记着上一个名字因此只能出站用短名）。
新名短、易入句，**在"会不会被模型当普通词写进正文"这一维上，两个名字的性质本来就不同。**

**由此定死两条读法**：

1. **旧名的 0 次不预测新名的 0 次。** 第一批（`cee46fb`，土拨鼠）对照臂两侧都是 0，
   **那个结果不能顺延到本批**——本批的 0 必须自己测出来。
2. **若新名 >0 而旧名历来 0，不许归因于"改名这个动作"。** 两者不是同一个词，
   **混淆变量是"名字本身"（长度、构词、是否含敏感词），而不是"改了名"。**
   正确写法：**「短名 `土八鼠` 下出现了 N 次；长名下未出现过」**——陈述两个事实，不搭因果。

**对照臂照旧数全部历史自称**（`SELF_NAMES` 只增不删）：`裁员应对专员` / `土拨鼠劳动仲裁` / `土八鼠`。
**旧名残留在输出里是改名最可能的失败形态**，只数新名会漏掉它。
（仓里现存的旧名引用已核：`notify/copy.ts` 与 `copy.test.ts` 是**守卫的输入清单**——
它断言这些旧名不许出现，所以必须包含它们；另一处是我自己的名字表。**零残留。**）
