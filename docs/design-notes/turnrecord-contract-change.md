# TurnRecord 契约变更说明（第三批备料，批后落）

变更两项（manager 队列）：**coreKeyCount 轮级粒度**、**⭐段在场随轮回传**。
两项**必须同批**——都改同一个契约，分开会让评测侧适配两次。

---

## 一、变更内容

```ts
export interface TurnRecord {
  // …现有字段不动…
  /** 本轮 ⭐ 核心条候选池（逐轮，非整场聚合）。
   *  空数组 = 机制跑了但没料；字段缺失 = 这份产物是旧版本，不知道。 */
  coreArticleKeys?: string[];
  /** 本轮 ⭐ 段是否真的出现在 system prompt 里，及含哪几条。 */
  coreBlockRendered?: { present: boolean; articles: string[] };
}
```

**两个字段都可选**——旧产物没有它们，回放必须仍能跑（见 §四）。

---

## 二、消费方清单（改契约前必须逐个看过）

### 产线侧（app/src）

| 位置 | 现状 | 本次变更 |
|---|---|---|
| `orchestrator.ts` runTurn | 逐轮已算出 `coreSources`/`coreArticleKeys(...)` | **新增写入点**：把本轮候选池与 ⭐ 段在场事实写进回传结构 |
| `prompt.ts` packsSection | 已收 `coreArticles` | 需回报「⭐ 段是否真渲染」——目前只有"传进去了"，没有"渲染出来了" |

> ⚠️ **这两件不是同一件事**：候选池非空 ≠ ⭐ 段出现（还要卡里有对应 statute_quotes 才渲染得出）。
> S03 那次的教训正是「我以为传了就等于给了」，所以**两个字段都要，不能只留一个**。

### 评测侧（scripts/eval，跨目录，需协调）

| 位置 | 用途 | 影响 |
|---|---|---|
| `eval-agent.ts:166,179` | 构造 `TurnRecord[]` | **必须填新字段**，否则判据永远看到 `undefined` |
| `eval-agent.ts:210,213` | `TurnRecord['actionCards' / 'drafts']` 取类型 | 无影响 |
| `assertions.ts:41` | 接口定义 | 若评测侧另有一份定义，**必须与产线同源**（否则又一次分叉） |
| `assertions.ts` 全部断言（约 20 处签名） | 只读现有字段 | 无影响（新字段可选） |
| 证据产物 JSON（`results/*.json`） | 落盘 | **产物 schema 变化** → 回放脚本要能读旧产物（§四） |

### 已录产物（不可改）

`results/**/*.json` 里**所有历史转录都没有这两个字段**。任何依赖它们的判据**必须能区分**：
「这份产物不知道」与「机制真的没产出」。

## 三、判据侧语义（manager 已钉）

> **产出为空 ⇔ 机制不可用。**

落到字段上必须是**三态**，不是布尔：

| 字段值 | 含义 | 判据处置 |
|---|---|---|
| 字段缺失（`undefined`） | **这份产物不知道**（旧版本） | **跳过该判据**，不计过不计挂；不得当成"机制不可用" |
| `[]` / `{present:false}` | **机制跑了，产出为空** | 判「机制不可用」——这是真信号 |
| 非空 | 机制可用 | 正常判定 |

**这是 A3「不知道 ≠ 零」的直接应用**，也是我们在 `openerPhones` 上已经踩过一次的坑：
`undefined` 与 `[]` 合并成 falsy，会把「旧产物」和「机制真的空了」判成同一件事，
而后者恰恰是最该报警的那个。

---

## 四、回放兼容（这条最容易漏）

改契约后，**历史产物回放不能挂**。要求：

1. 读旧产物时新字段为 `undefined`，判据走"跳过"分支，**不报错、不误判**；
2. 回放脚本按 A9 纪律**先打印样本命中量**：「N 轮里有 M 轮带 coreArticleKeys」——
   M=0 时**显式告警**（可能是字段没写进去，而不是真的都没料）；
3. 新旧产物混跑时，成绩单要能分辨哪些轮是"不知道"，不与"机制不可用"混计。

---

## 五、落地顺序与验收

```
1. 产线侧写入（orchestrator + prompt 回报）   ← app/src，我可做
2. TurnRecord 接口加两个可选字段              ← 契约，需两侧同源
3. 评测侧构造处填字段                          ← scripts/eval，agent2
4. 判据侧三态处置 + 回放跳过分支               ← scripts/eval，agent2
5. 单测：三态各一例 + 旧产物回放不挂            ← 两侧各自补
6. 一次冒烟：新产物字段非空、旧产物回放正常
```

**验收硬条件**：
- 三态单测齐（`undefined` / 空 / 非空 各一例，且**断言三者处置不同**）；
- **旧产物回放零改动可跑**（拿 `results/` 里任一历史 JSON 验）；
- 候选池非空但 ⭐ 段未渲染的样本**能被区分出来**（这正是 S03 那次没被发现的形态）。

---

## 六、一句提醒

这次改的是**可观测性**，不是判定逻辑——**但它会立刻改变成绩单的读法**：
以前「⭐ 没生效」只能靠人去翻转录，以后是一个字段。
所以**三态必须一开始就分清**：否则我们只是把"看不见"换成了"看见一个会骗人的数"。
