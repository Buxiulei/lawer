# 心跳唯一真源 · 迁出 git 工作树（manager 2026-08-25 裁定）

## 问题

同一份心跳文件**全机 10 份副本，每个 worktree 一份，内容各不相同**。
哨兵读主检出那份，后台技术写自己分支那份——**写的人和读的人站在不同的文件前面**。

**根因（manager 自领）**：**心跳是运行时状态，不是版本化产物**；
而批准 worktree 隔离时，**没想过"工作树里还住着不属于代码的东西"**。
> **同一个设计，在单检出下正确，在多 worktree 下崩溃——作用域一换，风险量级完全不同。**

## 裁定：移到 worktree 无关路径 `~/caiyuan-ws/heartbeats/<角色>.txt`

## 否掉的方案（记下来，否则只会留下结论）

**方向一：全员改写主检出 `/home/roots/裁员应对员/lawer/...`。否掉，两个理由**：

1. **它现在挂在 `ws/referral` 分支上——而它在哪个分支是偶然的（谁最后切的）。**
   **把唯一真源建立在一个偶然状态上不行。**
2. **只要它还在工作树里，下次有人再开一个 worktree，分叉就会重现。**
   ——**修的是这一次的症状，不是产生分叉的机制。**

## 迁移必须带三件（缺一就会重演）

| # | 动作 | 为什么 |
|---|---|---|
| ① | **旧位置改成一行指针，不删** | **删了之后，习惯性去那个路径的人会以为文件丢了；留指针才能把人导过去** |
| ② | **哨兵改读新位置，且巡逻脚本里路径写死** | **不许再按"当前工作目录"推算——那正是知识库 cwd 那个缺陷的同一形态** |
| ③ | **新位置不进 git，但在 `docs/OPS.md` 与 `TEAM-PROTOCOL` 写明它在哪** | 运行时状态不该被版本化；而位置要写在**使用者的动线上**（A86） |
