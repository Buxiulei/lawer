# 心跳唯一真源 · 迁出 git 工作树（manager 2026-08-25 裁定）

## 问题

同一份心跳文件**全机 10 份副本，每个 worktree 一份，内容各不相同**。
哨兵读主检出那份，后台技术写自己分支那份——**写的人和读的人站在不同的文件前面**。

**根因（manager 自领）**：**心跳是运行时状态，不是版本化产物**；
而批准 worktree 隔离时，**没想过"工作树里还住着不属于代码的东西"**。
> **同一个设计，在单检出下正确，在多 worktree 下崩溃——作用域一换，风险量级完全不同。**

## 裁定：移到 worktree 无关路径 `~/caiyuan-ws/heartbeats/<角色>.txt`

## 否掉的方案（记下来，否则只会留下结论）

**方向一：全员改写主检出 `/home/roots/裁员应对员/lawer/...`。否掉，两个理由**：

1. **它现在挂在 `ws/referral` 分支上——而它在哪个分支是偶然的（谁最后切的）。**
   **把唯一真源建立在一个偶然状态上不行。**
2. **只要它还在工作树里，下次有人再开一个 worktree，分叉就会重现。**
   ——**修的是这一次的症状，不是产生分叉的机制。**

## 迁移必须带三件（缺一就会重演）

| # | 动作 | 为什么 |
|---|---|---|
| ① | **旧位置改成一行指针，不删** | **删了之后，习惯性去那个路径的人会以为文件丢了；留指针才能把人导过去** |
| ② | **哨兵改读新位置，且巡逻脚本里路径写死** | **不许再按"当前工作目录"推算——那正是知识库 cwd 那个缺陷的同一形态** |
| ③ | **新位置不进 git，但在 `docs/OPS.md` 与 `TEAM-PROTOCOL` 写明它在哪** | 运行时状态不该被版本化；而位置要写在**使用者的动线上**（A86） |

## 迁移隐患三条（2026-08-25 傍晚，评测官提两条 + 实测补一条）

### ① 「把自己那份 cp 过去」有歧义 —— 可能把陈旧副本立成新的唯一真源

各角色的**实时**文件在**不同的树**（评测官/后台技术在 `lawer`，**外勤在 `knowledge`**）。
若有人在自己 cwd 那棵树里 `cp`，**而那份是旧 commit 物化出来的**（最旧的只有 72 行），
**就会把陈旧版本立成新的唯一真源，且此后不可发现**——因为新位置只有一份，没有东西可比。

> **安全口径**：**跨全机找齐 → 取行数最多且 mtime 最新 → 确认是自己今天写的 → 再 cp。**
> ⚠️ 注意此处 mtime 只用作**辅助筛选**，最终仍以**内容**确认（见 A84 推广：mtime 是检出产物）。

### ② `git rm --cached` 之后，各树已物化的副本不会消失 —— 会变成**僵尸副本**

**它比陈旧副本更骗人**：
> **mtime 永远停在 untrack 那一刻，看上去像"这个角色那天之后就没动静了"。**

**⇒ 同一提交里各树删一次 + 旧位置留指针**（与本文件上方三件中的①合并执行）。

### ③ `hb.sh` 的写入不是原子的 —— **失效方向正好制造它要防的假信号**（实测）

`hb.sh` 逻辑已实测正确（首行不堆积、首行时间与最后一条正文时间一致）。
但第 16 行是 `{ ... } > "$F"`：**直接截断并覆盖真文件**。
**若在写入过程中被中断，心跳档会被截断甚至清空**——
> **而"心跳档是空的"正是巡逻判"这个人死了"的信号。**
> **一个防止误判停摆的工具，它自己的崩溃方式就是制造一次停摆假象。**

**修法一行**：写临时文件后 `mv`（同文件系统内 rename 是原子的）：
```sh
{ printf '# 更新时间: %s\n' "$TS"; cat "$F.tmp"; } > "$F.new" && mv "$F.new" "$F"
```
