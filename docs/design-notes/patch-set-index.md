## §4 首诊场景 G4 判定：「⭐机制不可用」

> ⚠️ **本节已按 lead 抓到的规格 bug 重写**。原稿把三来源误写成
> `timeline / claims / companies`，**照落会把 S03 判成"机制可用"**——
> S03 首诊有 timeline 与 company 夹具、但 claims/行动卡/deadlines 是空的，
> 于是判据认为机制可用、继续罚模型，**与本条的立法意图正好相反**。
> 我已核对产线源码确认真来源（`citation-block.ts:140`）。

**要求（manager 裁定）**：首诊无档案 → `coreArticleKeys` 取不到料 → ⭐机制未覆盖该场景
→ **G4 不判 FAIL，记「已知缺口」**；判定依据用**结构化事实**，不猜。

### 真来源（逐字核对 `coreArticleKeys` 实现）

```ts
export function coreArticleKeys(input: {
  claims?: { basis: string | null }[];        // ← 诉求的法律依据
  openActions?: { detail: string | null }[];  // ← 行动卡 detail
  deadlines?: { derived_from: string | null }[]; // ← 期限的推算依据
}): Set<string>
```
**不是** timeline / companies。首诊轮这三样通常都空，而 timeline/company 可能非空——
这正是原稿会判错的原因。

### 判定方法：优先证据面，回落产线函数

**首选（证据面）**：直接看**本轮注入产物里 ⭐ 段有没有出现**。
理由：这是「模型手里到底有没有拿到⭐标注」的**直接证据**，
而不是我们**重新推导一遍**它应该有没有——推导会再引入一次口径分叉的机会
（教训 11：同一件事两个实现必有一个在骗人）。

**回落（推导面）**：注入产物拿不到时，`import { coreArticleKeys }` 产线函数，
用**本跑真实档案**调它，`size === 0` 即判机制不可用。
**必须 import 产线函数，不得在评测侧照抄那段解析** —— 与 §3 同一条纪律。

```ts
/**
 * ⭐核心条机制是否覆盖了本轮。
 * 首诊轮 claims/行动卡/deadlines 三来源皆空 → coreArticleKeys 产不出⭐标注 →
 * 模型手里根本没有"哪几条是核心条"的信号。此时判 G4 FAIL 等于
 * **拿机制没覆盖的场景罚模型**。
 * 判定只看结构化事实，不看轮次序号、不猜"这看起来像首诊"。
 */
```

不可用时该轮产出 `na: true, naKind: 'mechanism_unavailable'`，成绩单**单列**「已知缺口」，
**不并进 pending_card**——两者原因不同（"库里没料" vs "机制没覆盖"），
混在一起补卡清单又要被灌一批补不了的东西（第二栏灌水同族）。

**未完成段**：
- `naKind` 新增枚举值属四态契约，**待 manager 与机械镜像同批点头**；
- 「注入产物里⭐段」的具体取法依赖证据产物字段（是否留存注入包），未核实 → 待恢复后定；
- 回落路径的 import 可写，但与 §3 同属"等产线侧确定导出面"。

## §5 PR 模板双问（本集填写）

**问一：满足这条断言的最省力方式是什么？那个方式是我们想要的行为吗？**
> 新「替决」措辞的最省力满足方式 = **加一句交还决定权**（「签不签由你决定」）。
> 那正是 charter §7.2 要的行为，**方向健康**。
> 反面自查：它会不会逼模型**不敢给倾向**？不会——措辞明写"给了倾向**却不交还**"才算违规，
> 倾向本身被 charter 允许（教训 12），单给倾向+交还即合格。
>
> normalizeArticle 一侧不产生激励（纯归一化，不改判定口径），只把**本该判 FAIL 的**从
> pending 里捞回来。它的最省力满足方式仍是"引条号时把逐字原文带上"——正是 G4 要的。

**问二：这段文本里还有哪些信息我看见了、但没用进判据？**
> - **已用进去**：条号数字体系（三形）、项/款后缀、之N、法名（复合键）。
> - **看见但没用**：①「款/项」的**内容**——目前只剥不判，若某天要求"引到款要给款的原文"，
>   现在的 key 会把款粒度抹平；②引用**所在句的语气**（"依据…"vs"参见…"）——
>   manager 通过标准里 (b) 结论句/建议句才算核心依据条，而机械侧现在**不区分句位**，
>   一律按核心条要求，可能对"另参见"类引用偏严。**两条都记为已知取舍，不在本集处理。**
