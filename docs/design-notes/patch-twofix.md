## 修一：乙态检测容忍强调标记 + **节选闸**

**位置**：`scripts/eval/assertions.ts` → `unstructuredSourceArticles`

**病灶**：现行 `/^>\s*(第[…]+条)[　\s]/gm` 要求条号紧跟 `> `，而真实收录普遍写成
`> **第二十七条**　…`（粗体）。实测该模式在 `zhongcai-guanxia-shixiao.md` 上**整卡不开火** → 假零。

**改法**：
```ts
/** 收录行：条号可被粗体或下划强调标记包裹 */
const RECORD_LINE = /^>\s*(?:\*\*|__)?\s*(第[一二三四五六七八九十百零〇0-9]+条)(?:\*\*|__)?[　\s]/gm;
/** 节选标记：块内出现即**不算可结构化收录** */
const EXCERPT_MARK = /……|\.{3,}|节\s*选|（略）|\(略\)/;
// 取 at 所在的连续引用块（上下相邻的 `>` 行），块内含节选标记则跳过
```

**为什么节选闸比模式修更要紧**（写进注释）：
> 乙态的动作是派 WS4 把正文原文搬进 `statute_quotes`。把**节选**搬进去，会产出一张
> **自称逐字原文、实则缺款**的结构化卡；而 `statute_quotes.text` 是注入侧逐字原文的
> **唯一真源**，用户会拿它当庭念。**漏抓只是少派一张工单；误抓是造一个残缺的权威。**
> 两者代价不对称，所以宁可漏抓。

**测试（6 例，全部真卡）**：
- ★阳性：`zhongcai:76-79`（四款齐全）→ 开火
- 假零直证：旧模式在同一张真卡上 `test()===false`
- ★真卡负样本：`weiqian:89-90`（自标节选 + `……`）→ 不开火
- 真卡负样本：`tingqian:112-113`（散文引述，`（一）`开头）→ 不开火
- 负样本：正文交叉引用（非引用行）→ 不开火
- 已结构化的条不重复派单

## 修二：消费点迁移 `bareArticleSpans` 的 `{raw, at}`

**位置**：`scripts/eval/assertions.ts:~1207`（`citationCompletenessAssertions` 内）

**病灶**：产线**已备好** `bareArticleSpans`（`citation-block.ts:575`，返回 `{raw, at, article, site}`），
但消费端仍用 `bareArticleCitations(t.text)` + `t.text.indexOf(a)` 定位。
而 `bareArticleSpans` 内部 `raw = m[0].replace(/\s+/g,'')` **去了空格** →
原文写「第 40 条」时 `indexOf('第40条') === -1` → `at<0` →
`inner/adjacent/nearestLaw` **三条取法名的路整条跳过** → key 退化成 `|第N条` → 判 `pending_card`。

**语料规模**：带空格形 17 次 / 不带 35 次（评测官统计）——**约三分之一的引用**走这条路径。
方向是**漏判**（该 FAIL 的记成 pending，并把假 pending 灌进补卡清单）。

**改法**：直接迭代 spans，用 `span.at` 定位、`span.raw` 做键——**定位与归一分离**。
```ts
const cited = bareArticleSpans(t.text).map(({ raw, at, article }) => {
  const inner = /《([^》\n]{2,40})》/.exec(raw);
  const adjacent = /([一-龥]{2,20}(?:法|条例|办法|规定|解释|意见))\s*$/.exec(t.text.slice(Math.max(0, at - 24), at));
  const law = inner ? inner[1] : (adjacent?.[1] ?? nearestLaw(t.text, at));
  return { raw, law, article, key: citationKey(law, raw), hasLaw: !!law };
});
```
（`auxiliary` 那段已在用 spans，本改法与之统一，消费端从此只有一个取用面。）

### §3 ⚠️ 修二**不保证 §40 翻 FAIL**（实测限定，必须写进 PR）

真转录实测（`2026-08-22T18-00-35Z`，at=464）：
```
nearestLaw(t, 464)      → null        ← 默认 lookBehind=40，够不着
nearestLaw(t, 464, 80)  → 劳动合同法   ← 80 够得着
前文：…→ N（《劳动合同法》第 46 条第 2 项）；⏎- 无过失性辞退 / 经济性裁员 → N+1（第 40 条）
```
法名在**上一条列表项**里（并列列表省略法名，语义上确实指劳动合同法§40）。
**「要不要放宽 lookBehind」是独立的放松向改动**：放宽会增加**绑错法**的机会，
而绑错法是**看不见**的错（拿甲法的原文去要求乙法）。按 A7「向松动改需多份语料稳定证据」
与代码里既有的绑错法告诫，**本两修不含此项，另请裁**。

**测试（5 例）**：现状 bug 复现 / 修后定位成立 / **★§40 仍取不到法名（默认窗口够不着，80 够得着）** /
带书名号前缀不受窗口影响 / 不带空格的既有行为不变。

## 修一之五：乙态派单文案必带完整性核对句（manager 追加人工兜底）

**位置**：两处**同一句**——`assertions.ts` 乙态分支的 `detail`，与 `pending-cards` 侧的清单输出。

```ts
/** manager 2026-08-25 指定逐字：闸之外的最后一道人工兜底 */
const UNSTRUCTURED_DISPATCH_NOTE =
  '结构化前须对照官方全文核完整性；缺款缺项则补全后再提，补不全降级 pending_card';
```

**为什么闸之外还要人工兜底**（写进注释）：
> 节选闸认的是**卡自己的标记**（`……`/`节选`/`（略）`）——**没标注的节选，闸认不出来**。
> 所以最后一道完整性确认要写进 WS4/外勤的**动作**里：闸漏了，还有人在结构化前
> 对着官方全文核一遍。
>
> manager 定性：**「宁缺毋残是权威字段的铁律」**——`statute_quotes.text` 是注入侧
> 逐字原文的**唯一真源**，用户会拿它当庭念；**缺款的"逐字原文"比没有原文坏得多**。

**落码形态**：
```ts
detail: `${p.raw} 的逐字原文**已在卡正文里**，只是没进 statute_quotes → 派 **WS4 结构化**，` +
        `不进外勤补卡栏。${UNSTRUCTURED_DISPATCH_NOTE}。`
```

**测试（3 例）**：逐字比对 manager 指定文案／三要件齐（核完整性·补全后再提·补不全降级 pending_card）／
兜底句**必须出现在 detail 里**（不能只写在文档——写在文档里没人会在派单那一刻看到）。
