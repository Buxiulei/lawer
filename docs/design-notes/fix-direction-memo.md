## 二、A：归一化函数**行为侧与判据侧共用一份**

### 现状（分叉）

| 侧 | 函数 | 位置 |
|---|---|---|
| 判据 | `normalizeArticle` / `citationKey` | `scripts/eval/assertions.ts` |
| 行为 | `coreArticleKeys` 内联同款逻辑 | `app/src/lib/agent/citation-block.ts` |

**两处各写一份 = 教训 1 的形状**（判据同源）。本次 bug 恰好证明它：判据侧改了、行为侧没改，两边会静默漂移。

### 收敛方案

归一化实现放**产线**（`citation-block.ts`），**评测侧 import**——与 `bareArticleCitations` / `detectNbdpsyPitch` 同样的方向（产品定义判据，评测复用）。

```ts
// app/src/lib/agent/citation-block.ts（唯一真源）
export function normalizeArticleNo(raw: string): string   // 第46条第2项 → 第四十六条
export function normLawName(raw: string): string          // 《中华人民共和国劳动合同法》→ 劳动合同法
export function articleKey(law: string | null, article: string): string
```

要点：
1. **阿拉伯 → 汉字**（不是反向）——卡是权威侧，卡里存汉字，向卡看齐；
2. **剥项款**：`第46条第2项` → `第四十六条`（项款是引用精度，不是条的身份）；
3. **不做包含匹配**（短名吞长名，见 A5 已入册）。

## 三、B：核心条源要扩到**本轮可得的信号**

### 病理

`coreArticleKeys` 三个源全是**历史档案**（claims / 行动卡 / deadlines）。
**首轮场景**（用户刚开口，还没算过钱、没开过卡）→ 三源皆空 → ⭐ 块整段不输出。

**而首轮恰恰是引用质量最要紧的时刻**——用户马上要拿这些条文去谈判。

我当初写的「无核心条时不加段落，不让 ⭐ 变成装饰」是对的，
**错的是我没意识到"必然为空"这个时间性**，还把它写成单测当作正确行为固化了下来。

### 候选修向（择一或组合，需 manager 裁）

1. **本轮检索到的 statute 卡自身即核心**——模型这轮拿到哪几条，哪几条就是本轮该引全的；
   最简单、必然非空、且与"注入什么就该引什么"的直觉一致。**推荐**。
2. **用户消息命中的条号**：用户提到「N/2N/时效」等，反查对应条。覆盖面窄，作补充。
3. **场景 → 核心条映射表**：确定但要维护，且与"数据活性归卡"相悖，**不推荐**。

**若取 1**：注意别让"⭐ 全部命中"退化成"每条都是核心"——那等于回到被 manager 否掉的粗规则。
建议**上限 2–3 条**，按检索排序取前几，并在块里说明"其余可只给条号"。
