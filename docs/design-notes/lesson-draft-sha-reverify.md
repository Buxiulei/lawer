# 待入册教训草稿：验证结论不会自动跟着 SHA 走

> 状态：待 manager 判定后入册（team-lead 2026-08-22 排队）
> 归属建议：与「防过期前提」同族，但更具体——这次过期的不是数据，是**基线本身**

## 事件

2026-08-22，我在 `40e2bed` 上做完 G4 终验，结论是「六条法条主路的引用块全部拼得出来」，
并据此向上报了「三条主路全通」。

随后 lead 宣布 `8cea265` 为锁定候选。我在待命前顺手核了一句「我那份验证对候选还算不算数」：

```sh
git merge-base --is-ancestor 40e2bed 8cea265   # → 否
```

**`40e2bed` 根本不是候选的祖先**——分支在这中间被重写过，我验证的那个提交已经不在主线上。
而且 `git diff` 显示，那张六条法条卡本身有 **18 行改动**。

这次是虚惊：改动是纯增量（六条原文一字未动，逐条比对字数 203/215/384/280/216/61 全部一致，
只新增了实施条例两条）。**但如果那 18 行改的是六条原文本身，我那份「三条主路全通」
就已经过期，而没有任何机制会告诉任何人。**

## 为什么这类过期特别难发现

一份验证报告长成「结论 + 证据」的样子，**唯独不带它成立的前提**——
即「我是在哪个树的哪个状态上跑出这个结果的」。报告一旦发出去就脱离了那个状态，
而在这个项目里，基线每天被重写好几次（rebase / autostash / 候选平移）。

于是出现一种很干净的假象：**结论还在，证据还在，只有前提悄悄没了。**
读的人看不出差别——一份过期的验证和一份有效的验证，写出来一模一样。

（同族前例：#40 改机构名击穿按 name 匹配的断言；六条补卡前后 G4 挂点定性口径反转；
本次是同一个形状的第三次，只不过过期的东西从「卡里的数据」变成了「基线本身」。）

## 规矩

1. **验证结论必须带 SHA 落款**。「G4 三条主路全通」不是一个事实，
   「G4 三条主路在 `40e2bed` 上全通」才是。不写 SHA 的验证报告，等于不写有效期。
2. **基线变了就重验，别推断**。判断依据是 `git merge-base --is-ancestor <验证时的SHA> <当前候选>`：
   - 是祖先 → 结论可继承（但仍要确认相关文件没被后续提交改动）；
   - **不是祖先 → 分支被重写，一律重验**，不管改动看起来多无关。
3. **发版候选平移时，要连带重验挂在旧 SHA 上的所有结论**，不只是重跑测试。
   测试会自己跟着新树跑，而**人写的验证报告不会**——它躺在聊天记录里，看起来永远有效。
4. 推论到人身上：**"我验过了"是有有效期的说法。** 隔了一次 rebase 再引用自己的旧结论，
   与引用一份不知道什么时候的文档没有区别。

## 附则：SHA 必须可验证（收发两侧，2026-08-23 增补）

上面四条要求验证结论**写上 SHA**。附则要求**写上的那个 SHA 是真的**——两条是一对，
缺了后者，落款反而会给假 SHA 背书：**一份带着不存在 SHA 的报告，比不带 SHA 的报告
更容易被当成已核实。**

### 事件

manager 签收了一个仓库里根本不存在的 SHA `d5d5faf`。自查结论：**是他在写「签收」时
凭空合成的**——形如 7 位十六进制、看起来完全合理，但从未在任何地方存在过。

溯源时的关键一步是个**否定结果**：

```sh
git cat-file -t d5d5faf                      # → fatal: Not a valid object name
grep -rn "d5d5faf" <全部工作树> <全部评测产物> <草稿>   # → 零命中
```

**它不在任何文件里**——不是仓库对象，不在任何 META、log、产物或旧消息里。
如果是转述链某环抄错，源头总得先有个可抄的东西；**全线零命中意味着它不可能是抄来的**。
于是排查方向从「谁抄错了」收窄成「**谁在没有 git 输出可依的情况下写了一个 SHA**」，
与本人自认吻合。

### 规矩（两侧成对，成本都极低）

- **发件方**：消息里出现的 SHA，必须是**本轮刚从 git 输出读到的**（`git log` /
  `git rev-parse` / `git cat-file`），**不许凭记忆写**。记不清就现查，别补一个像样的。
- **收件方**：签收任何带 SHA 的结论前，`git cat-file -t <sha>` 一下——**一秒钟的事**，
  且这次就能当场拦住。

### 为什么这类错误特别容易发生

SHA 是**高熵但低语义**的字符串：人对它没有语感，写错一位读不出来，
凭空造一个也看不出来。**其它字段错了会读着别扭，SHA 错了只是"看起来像个 SHA"。**
所以它不能靠"仔细点"来防，只能靠机器一秒钟的存在性校验。
