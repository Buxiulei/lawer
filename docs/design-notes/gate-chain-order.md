## 二、表序 ≠ 源码行序：两处已登记的差异

1. **⑤⑥ 在流上。** 正文是流式下发的，等整轮跑完再发现编了案号，用户早读进去了。所以它们的调用点在 `runOnce` 里，行号早于 ②③④，而**文本流经的先后**仍是 ②③④ 拿到已过 ⑤⑥ 的正文。判据按 `stage` 分段核对，不拿行号硬比。
2. **④ 的调用点排在 ③ 之前。** ④ 的 `effect === 'observe'`——它一个字都不改，只发 notice；一道不改正文的闸，位置换到哪里都不改变用户看到的东西。**登记它而不是消灭它**：真去调换两块代码是一次没人要求的行为变更（④ 会改成读剥后正文），收益只是让表读起来整齐。判据里写死了「这处偏差的全部安全性来自它不改正文」——④ 一旦开始回写 `text`，判据立刻红。

## 三、相互作用（每对相邻闸一条用例，见 `gate-chain.test.ts` §三）

**每一条都真调用两道闸，且都带负对照。**（首轮里 ①→② / ②→③ / ③→④ 是对 orchestrator 源码的正则扫描、④→⑤ 的占位符是手写的——它们能证明"源码长这样"，证明不了"两道闸接触时会怎样"：把 ⑤ 从流上摘掉，④→⑤ 照样绿。源码扫描保留，它守的是接线点没被挪走。）

- **①→②** 模型段整段是杠杆时，② 必须**回落确定性兜底**。负对照：把含首段的全文当模型段喂进去，首段替模型段撑住了"剥完还剩东西"这个判断 ⇒ 不再回落，用户拿到首段 + 一段空白。
- **②→③** ② 剥完的正文进 ③，③ 只剥推介句；首段全程不参与两道剥除。负对照：不经 ② 直接给 ③，杠杆句留在正文里。
- **③→④** ③ 剥不剥推介句，④ 的判定**逐字相同**——这是差异 2 可被登记的全部理由（并附一条"样本确实触发了 ④"的前置断言，免得比较是空对空）。
- **④→⑤** 占位符由 ⑤ **自己产出**（`citations.push` + `flush`），不是手写的；④ 对它不报污染。负对照：⑤ 之前那一版**是**会报污染的。
- **⑤→⑥** `statutes.push(citations.push(chunk))`；流末 `statutes.push(citations.flush()) + statutes.flush()`。反过来 ⑤ 扣住的半截案号会绕过 ⑥。
- **⑥→⑦** ⑥ 的标记落在引号外，不影响 ⑦ 的引号内比对。
- **⑥→⑧** **不变量：⑧ 能补原文的每一条，⑥ 都必须放行。** 两者的取料面都是本轮 `state.retrieved` 的 `statute_quotes`，所以 ⑧ 永远找得到核心位。否则 ⑧ 会去给一个刚被标成【条号待核验】的位置补原文。**单行与多行各一条**——见下面「多行原文」。
- **⑦→⑧** ⑧ 补进来的是卡内逐字原文，再过一遍 ⑦ 也不会被剥；顺序反过来这条就红。
- **⑧→⑨** ⑧ 以 `「…」` 插入，落在 ⑨ 的引号免检面里——**⑧ 补一条原文，⑨ 不许因此多开一次火**。多行样本里放一个**期限语境里的日期**做隔离：金额与倍数有两道防线挡着（引号免检 + "原文里写着这个数"），日期只认 `deadline_list` 出参，所以它是引号免检那条的唯一隔离样本；不这么做，把免检改回按行算，用例照样绿。
- **⑨→⑩** ⑨ 的标记里不含承诺/边界字面，⑩ 接线当天不会对着我们自己的标记开火（用评测侧真正在用的 `OUTCOME_PROMISE` 验，不另写近似正则）。

### 多行原文：免检面必须跨行（首轮 blocker，2026-09-08 修）

⑧ 是把卡内原文以 `「…」` **内联**插进正文的，而真库 318 条 `statute_quotes` 里 **164 条是多行的**，其中相当一部分从第 2 行起才出现立法者的交叉引用（核心卡 §46 →「第三十八条」正是其一）。免检面若按**行**算（blockquote 看本行行首、引号看本行之前的奇偶），第 1 行豁免、第 2 行起不豁免，于是：

- ⑥ 的漏网自检把**闸自己刚补进来的原文**记成漏网 → `gate_report.leaked > 0` → 判据报「闸自己漏了」，而闸什么都没做错；
- ⑨ 对着条文里的数字开火，标出【数值无来源】。

修法：**非对称引号（`「」『』“”`）的免检跨行**（开闭是不同字符，跨多少行都配得准），实现只有一份——`citation-block.ts` 的 `insideVerbatim`，⑥⑦⑧⑨ 共用；⑨ 此前手抄的那份按行实现已删。**对称的 `"` 仍按行内奇偶**：它开闭同形，跨行配对必然把两段正文之间的部分当成引文。未闭合的开引号最远罩 `ASYM_QUOTE_CAP = 3000` 字（真库最长原文 912 字，留三倍余量）——不设上限的形态是模型漏打一个 `」`，从那个字起闸永久关闭，而 `gate_report` 会诚实地报「候选 0 处」。⑥ 在流上没有"往后看闭引号"这回事，所以它按同一个上限**数着字**收回免检态，两边口径逐字一致。

判据：`__tests__/real-corpus-gate-chain.test.ts` 拿**真知识库全量**逐条跑 ⑥→⑧→⑨，只问"闸对自己的产物开不开火"。合成样本证明不了这件事——首轮的交互用例全是单行原文，全绿。

## 四、gate_report：两个率必须一起读

`GATE_REPORT` notice 带结构化 `gate_report`。**notice 归 notice（给人看）、gate_report 归 gate_report（给机器读）**，判据只读后者，不从 message 里解析中文数字。

- **替换率** = 动手 / 候选，只算 `RATE_GATES`（⑤⑥⑦⑨）。①②③④ 没有"候选数"这个分母（危机轮开没开火是 0/1 事件，与"12 处引用里换了 1 处"不可通约）；⑧ 是**补入**不是替换，记进分子等于把我们做对的事记成闸误伤。
- **漏网率** = 闸跑完后用户面仍未标注且不在放行集里的引用 / 候选。结构上恒 0。
- **预算 2%**（设计稿 §4.3 初值）。超预算 = **闸误伤，不是模型变差**——处置是去查闸的判据（放行集取材面、免检态），不是去调提示词。**只点名，不阻断**：做成阻断会让人为了发版去放松闸，方向正好反了。
- 只报一个率的形态：闸把什么都替换掉（率高、漏网恒 0）看起来"守得很严"；或闸一处不换（率 0）而漏网全靠没人看。
- **两个单列计数**，都不进率：`statute_ambiguous`（⑥ 明说不判的序数量词歧义，见 §五-0）与 `statute_doc_rejected`（文书通道拒收，见 §六）。合进率里，前者会把闸的自我克制记成误伤，后者会把闸做对的事记成误伤。
- **放行集 `statute_allowed` 挂在 `GATE_REPORT`（无条件发）上，不挂 `STATUTE_UNVERIFIED`（只在开火时发）。** 挂错的形态是：模型全引对的干净轮归档里没有放行集，判据读成空集——而**空放行集是最强的判定前提**，它让用户面每一处真放行的条号都成为漏网，L1 在最理想的一轮恒红，还与同轮 `leaked: 0` 当场打架。归档侧同理：`statuteGate` 只有两态（对象 = 跑了、`null`/缺失 = 不可判），没有"跑了但没开火"这个第三态。

## 五、明说的缺口与待接项

0. **⑥ 不判裸的「第一条」…「第十条」。** `第N条` 在中文里同时是条号与序数量词（「我给你三条建议。第一条，先别签字。」「第三条路是走仲裁。」）。这个歧义在 ⑥ 只留痕时无害，改成 `rewrite` 之后直接把【条号待核验】写进一段正确的话里，还计进替换率——读报表的人会以为模型在编条号。判据是**形态**：带《法名》、带款/项、或条号 > 10 三者之一即按条号处置；三者都不满足的裸条号不判。方向由后果定：误伤是把正确的话弄脏并计进闸的成绩，漏拦是少标一处。**洞有多大每轮看得见**——`gate_report.statute_ambiguous` 单列计数，成绩单单起一行；只写在注释里的缺口，在报表上与"没有这个缺口"同形。真语料里裸的低位条号几乎总带着法名（`《某某法》第八条`），而序数用法几乎总是裸的。

1. **⑨ 不捕裸 `N`。** 在这个行当里 `N` 是某项补偿的通称（「先把 N 算清楚」），不是数值断言；单字符 `N` 在中英混排正文里到处都是。捕它的误伤面远大于收益。带系数的形态（`2N`/`3N`/`N+1`）才是断言，设计稿点名的负样本「按 3N」正属这一类。这是**声明的缺口，不是遗漏**。
2. **登记簿 `source_status` 未接上。** `knowledge/sources.json` 已在树上并带 `status`，但 `facts.statute_quotes` 还没有 `source_id`，所以这一格现在恒为 `undefined`。三态处置已经写好（`undefined` 按现行处理 / `现行` 放行 / 其余标【已修正，见新版】且禁止进文书），`gate_report.source_status_unknown` 单列计数，成绩单单起一行——**"我们不知道"与"它是现行"不许在报表上同形**。知识层接上 `source_id` 之后这个数应归零。
3. **⑩ 未实现**，见上。

## 六、禁令必配出路（设计稿 §7.7）

每一处标记都带出路，且**两种标记的出路不同**：

| 标记 | 出路 |
|---|---|
| 【条号待核验】 | 点开来源卡看我们手上有哪几条；或让我们用 `citation_check` 取原文 |
| 【已修正，见新版】 | 这一条不要往文书里写；回一句「取新版」 |
| 【数值无来源】 | 回一句「帮我算一下」，走 `claim_calc`，算式 + 输入来源 + 依据条文一起给 |
| 【数值与来源卡不一致】 | 以来源卡为准，点开来源卡看生效期间 |

正文里是**标记**（用户还能自己判断），文书通道是**拒收**（材料递出去之后标记跟着一起交到对面手里）。文书拒收那条 notice 同样带出路：「我这就去把这几条的原文取回来再重写；你也可以回我一句『查一下这条』，或者先看回复里的来源卡」——拒收对用户是**什么都没发生**（文书没生成、正文里也没有标记），不给出路他只知道"有个东西被拒了"。

**两条通道分账**（首轮把它们记在一起，2026-09-08 修）：`StatuteGuard.found`/`seen` 只记正文，`docFound`/`docSeen` 只记文书。合账会同时说两句假话——轮末 notice 对用户说「已标注【条号待核验】」而正文里一个标记都没有；替换率把拒收算进分子分母（文书错 1 处 + 正文 1 处引用 ⇒ 报 50%、点名「闸误伤」，而闸做的恰恰是它该做的事）。文书拒收数走 `gate_report.statute_doc_rejected` 单列。

## 七、⑨ 的放行来源是五份，不是设计稿字面的两份

设计稿写的是「∈ `claim_calc` 出参 ∪ `retrieved` 的 `facts.values`」。照字面实现跑出来的形态是：用户说「我月薪 2 万、公司裁了 3 万人里的 1%」，模型**复述**这几个数，三处全被标【数值无来源】——而这正是 ⑨ 自己在日期那一段写明要避免的事：**系统去质疑用户对自己的事的陈述**。法定倍数同理：「2 倍工资」的来源是条文本身，而给出的出路「用 `claim_calc` 算」根本算不出一个法定倍数。它们是每轮几乎必现的数字类别，漏掉就会把 2% 的预算顶穿，而超预算的处置是「按闸误伤查闸」——闸每天给自己制造一次复查。

| 来源 | 是什么 | 为什么它算来源 |
|---|---|---|
| `claim_calc` 出参 | 结构化事实 | 算出来的数才准出现在正文里 |
| `retrieved` 的 `facts.values` | 结构化事实 | 卡里的值，带生效期间与可信度 |
| `retrieved` 的 `statute_quotes` 原文 | 结构化事实 | 法定倍数/比例的来源就是条文；跨数字体系互认（条文「二倍」↔ 正文「2 倍」，「百分之四十五」↔「45%」），走 `cnNumeral` 这个唯一真源 |
| 档案里的结构化事实（月工资等） | 用户自己的事实 | 他自己填进档案的，复述它不是编造 |
| 用户自己说过的话 | 用户自己的事实 | **取材面与杠杆闸的 `userTurns` 逐字同源**——复述用户原话在那边不算杠杆，在这边同样不算无来源；两道闸对同一段话给相反判断，用户看到的就是一个自相矛盾的产品 |

比对带**类别**（`金额:20000` / `百分比:3` / `倍数:2`）：只比数字的形态是卡里有个「3 倍」、模型写「3 元」也放行，闸变成一张只看数字的白名单。

**约写放行**：按 token 自己写的位数四舍五入后与卡值相等即放行（47103.25 → 「约 4.71 万元」「4.7 万」）。封顶数在真语料里几乎总以万元约写出现，按容差判会落进【数值与来源卡不一致】——那句话对读者说的是"你抄错了"，而他抄对了、只是四舍五入。判据是**位数**而不是"差得少"：`47100 元` 写到个位却不等于 47103，仍是不一致——它声称的精度就是个位，那一位是错的。
