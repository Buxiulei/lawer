# 闸链顺序表（S2 闸链补齐，2026-09-08）

设计依据：`docs/design/legal-agent-architecture.md` §4.3（闸链顺序与相互作用）、§1.3（失败模式与唯一拦截层）、§5 第 2/3 项、§7.3、§7.7。

**代码真源**：`app/src/lib/agent/gate-chain.ts` 的 `GATE_CHAIN`。本文件是它的说明，**不是第二份定义**——顺序改动改代码常量，判据（`__tests__/gate-chain.test.ts`）会当场红。

## 一、顺序

| # | 闸 | 作用 | 物理位置 | 自己的 notice | 状态 |
|---|---|---|---|---|---|
| ① | 危机首段 | prepend | post | —（确定性首段，没有"开火"这回事） | live |
| ② | 杠杆闸 | rewrite | post | `EMOTIONAL_LEVERAGE_DETECTED` | live |
| ③ | NBDpsy 推介闸 | rewrite | post | `NBDPSY_PITCH_BLOCKED` | live |
| ④ | 判例污染 | observe | post | `PRECEDENT_CONTAMINATED` | live |
| ⑤ | CitationGuard（案号） | rewrite | **stream** | `CITATION_BLOCKED` | live |
| ⑥ | StatuteGuard（条号） | rewrite | **stream** | `STATUTE_UNVERIFIED` | live |
| ⑦ | stripUnsupportedQuotes | rewrite | post | `CITATION_BLOCKED` | live |
| ⑧ | renderCoreArticleFallback | rewrite（**增**） | post | `CORE_ARTICLE_RENDERED` | live |
| ⑨ | ValueGuard（数值） | rewrite | post | `VALUE_UNSOURCED` | live |
| ⑩ | 承诺/边界字面表 | rewrite | post | `PRACTICE_BOUNDARY_BLOCKED` | **planned** |

⑪「争点回声」是评测侧判据，不是产线闸，故不在表内。

**⑩ 未实现**（设计稿 §5 第 9 项，另属一片）。顺序先钉住，是为了防止日后接线的人把它插在 ⑨ 之前——那样它会去判 ⑨ 刚插进正文的标记文本。

## 二、表序 ≠ 源码行序：两处已登记的差异

1. **⑤⑥ 在流上。** 正文是流式下发的，等整轮跑完再发现编了案号，用户早读进去了。所以它们的调用点在 `runOnce` 里，行号早于 ②③④，而**文本流经的先后**仍是 ②③④ 拿到已过 ⑤⑥ 的正文。判据按 `stage` 分段核对，不拿行号硬比。
2. **④ 的调用点排在 ③ 之前。** ④ 的 `effect === 'observe'`——它一个字都不改，只发 notice；一道不改正文的闸，位置换到哪里都不改变用户看到的东西。**登记它而不是消灭它**：真去调换两块代码是一次没人要求的行为变更（④ 会改成读剥后正文），收益只是让表读起来整齐。判据里写死了「这处偏差的全部安全性来自它不改正文」——④ 一旦开始回写 `text`，判据立刻红。

## 三、相互作用（每对相邻闸一条用例，见 `gate-chain.test.ts` §三）

- **①→②** 首段不进杠杆闸：判的是 `modelBody`，不是含首段的 `text`。
- **②→③** ③ 同样先 `splitCrisisOpener` 再判/剥，首段那句合法的引导语不参与剥除。
- **③→④** ④ 只发 notice 不动正文——这是差异 2 可被登记的全部理由。
- **④→⑤** ④ 读的是过完 ⑤ 的正文：【案号待核实】占位不会被当成案号。
- **⑤→⑥** `statutes.push(citations.push(chunk))`；流末 `statutes.push(citations.flush()) + statutes.flush()`。反过来 ⑤ 扣住的半截案号会绕过 ⑥。
- **⑥→⑦** ⑥ 的标记落在引号外，不影响 ⑦ 的引号内比对。
- **⑥→⑧** **不变量：⑧ 能补原文的每一条，⑥ 都必须放行。** 两者的取料面都是本轮 `state.retrieved` 的 `statute_quotes`，所以 ⑧ 永远找得到核心位。否则 ⑧ 会去给一个刚被标成【条号待核验】的位置补原文。
- **⑦→⑧** ⑧ 补进来的是卡内逐字原文，再过一遍 ⑦ 也不会被剥；顺序反过来这条就红。
- **⑧→⑨** ⑧ 以 `「…」` 插入，天然落在 ⑨ 的引号免检面里——**⑧ 补一条原文，⑨ 不许因此多开一次火**。
- **⑨→⑩** ⑨ 的标记里不含承诺/边界字面，⑩ 接线当天不会对着我们自己的标记开火（用评测侧真正在用的 `OUTCOME_PROMISE` 验，不另写近似正则）。

## 四、gate_report：两个率必须一起读

`GATE_REPORT` notice 带结构化 `gate_report`。**notice 归 notice（给人看）、gate_report 归 gate_report（给机器读）**，判据只读后者，不从 message 里解析中文数字。

- **替换率** = 动手 / 候选，只算 `RATE_GATES`（⑤⑥⑦⑨）。①②③④ 没有"候选数"这个分母（危机轮开没开火是 0/1 事件，与"12 处引用里换了 1 处"不可通约）；⑧ 是**补入**不是替换，记进分子等于把我们做对的事记成闸误伤。
- **漏网率** = 闸跑完后用户面仍未标注且不在放行集里的引用 / 候选。结构上恒 0。
- **预算 2%**（设计稿 §4.3 初值）。超预算 = **闸误伤，不是模型变差**——处置是去查闸的判据（放行集取材面、免检态），不是去调提示词。**只点名，不阻断**：做成阻断会让人为了发版去放松闸，方向正好反了。
- 只报一个率的形态：闸把什么都替换掉（率高、漏网恒 0）看起来"守得很严"；或闸一处不换（率 0）而漏网全靠没人看。

## 五、明说的缺口与待接项

1. **⑨ 不捕裸 `N`。** 在这个行当里 `N` 是某项补偿的通称（「先把 N 算清楚」），不是数值断言；单字符 `N` 在中英混排正文里到处都是。捕它的误伤面远大于收益。带系数的形态（`2N`/`3N`/`N+1`）才是断言，设计稿点名的负样本「按 3N」正属这一类。这是**声明的缺口，不是遗漏**。
2. **登记簿 `source_status` 未接上。** `knowledge/sources.json` 已在树上并带 `status`，但 `facts.statute_quotes` 还没有 `source_id`，所以这一格现在恒为 `undefined`。三态处置已经写好（`undefined` 按现行处理 / `现行` 放行 / 其余标【已修正，见新版】且禁止进文书），`gate_report.source_status_unknown` 单列计数，成绩单单起一行——**"我们不知道"与"它是现行"不许在报表上同形**。知识层接上 `source_id` 之后这个数应归零。
3. **⑩ 未实现**，见上。

## 六、禁令必配出路（设计稿 §7.7）

每一处标记都带出路，且**两种标记的出路不同**：

| 标记 | 出路 |
|---|---|
| 【条号待核验】 | 点开来源卡看我们手上有哪几条；或让我们用 `citation_check` 取原文 |
| 【已修正，见新版】 | 这一条不要往文书里写；回一句「取新版」 |
| 【数值无来源】 | 回一句「帮我算一下」，走 `claim_calc`，算式 + 输入来源 + 依据条文一起给 |
| 【数值与来源卡不一致】 | 以来源卡为准，点开来源卡看生效期间 |

正文里是**标记**（用户还能自己判断），文书通道是**拒收**（材料递出去之后标记跟着一起交到对面手里）。
