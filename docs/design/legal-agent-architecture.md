# 法律智能体设计：通用思想与土八鼠落法

> 2026-09-06 · 主会话（Fable 5.1）综合。输入：三路调研（`legal-agent-inputs/r1-landscape.md` 外部现状与幻觉证据、`r2-datasources.md` 中国法律数据源与合法获取、`r3-current-arch.md` 土八鼠现状与 15 条事故）、五份独立方案（接地 81/80/70、法律方法 79/79/64、安全评测 76/71/74、用户旅程 72/56/65、平台多领域 67/68/64，三位评审分别从严谨性、用户与合规、可落地打分）。本稿以**接地方案为引用链骨架、法律方法方案为推理骨架**，嫁接其余三份被评审点名的机制，并补上五份方案都没答好的八个问题（§7）。
>
> 适用范围：先是土八鼠（劳动 → 心理咨询纠纷 → 婚姻家庭 → 一般民事），但 §1–§3 的思想是通用的：任何「给非专业人士提供法律帮助的 agent」都适用。

---

## 0. 一页结论

**一个好的法律智能体，不是「答得像律师」，而是「每一句能被对方律师当庭查而不倒」。** 实现它的方式不是更好的提示词，而是：

1. **模型不是防线。** 可靠性押在确定性闸、结构化中间产物与服务端工具上；模型只做两件事——把用户的话映射到槽位、把结构化结果写成人话。
2. **每一句法律断言都是三元组〈断言，锚点，核验状态〉。** 锚点指向官方原文（法条/文号/官方案例页）或带来源的档案事实；没有锚点的断言要么出不来、要么带着【待核验】出来。
3. **不可逆的事从模型路径上移走。** 法定期限、签字/辞职/发函前的拦截、情绪危机首段——由程序产出，模型不参与。
4. **未记录 ≠ 不存在；自述 ≠ 书证。** 要件三态（成立/缺失/不成立）与来源四档（自述/书证/对方认可/裁审认定）是类型，不是提醒。
5. **用户在哪，闸就在哪。** 站内对话、MCP、REST、无工具粘贴回贴四条路径过同一条闸链；控制不了对方模型时，控制它拿到的原料和它写进档案的内容。
6. **判据先于机制。** 每道闸一条会红的测试；每个目标先按 SHA 记基线再优化；量具（judge）先审再信读数。
7. **禁令配出路。** 闸开火之后，用户和 agent 都要有下一步；诚实降级要看起来像尽责，不像软弱。
8. **领域是配置加内容，内核去领域化。** 新领域上线有准入清单，不是「再写一遍」。
9. **执业边界由结构保证。** 工具面里根本没有「代理、递交、代言」的动作；字面闸只是兜底；不靠话术纪律。

对土八鼠现状，最值得先做的三件事（三周内可上、可验）：**法源登记簿与可信度封顶**（103 张判例卡里 68 张首源是转载站却可能标「原文核实」）、**条号运行时闸 StatuteGuard**（现在光秃条号只记通知不动正文）、**程序化期限**（stage 变更服务端自动落期限，模型退出期限路径）。

## 1. 目标函数与失败模式（通用）

### 1.1 「好」的定义

用户在当前阶段的每一轮对话后，能说出三件事：**我的诉求靠哪几条事实成立（要件）；哪几条还缺证据或该对方证明（争点与举证）；下一步动作与不能错过的日期（行动卡与程序节点）。** 三件事全部可回溯到档案字段与官方原文。「答得多」不是目标。

### 1.2 可量化判据（每项先按 SHA 记基线，再定目标）

| 指标 | 判据 | 目标 | 层 |
|---|---|---|---|
| 案号可回溯 | 输出中每个案号 ∈ 本轮检索原文 | 100%（红线） | 闸 |
| 条号可回溯 | 每个「《X法》第 N 条」∈ 本轮 statute_quotes ∪ 已取原文的核心条 | 100% | 闸 |
| 逐字一致 | 引号内条文与卡内原文空白归一后一致 | ≥98%，差异必标【转述】 | 闸 |
| 数值有来源 | 带单位的金额/倍数/百分比 ∈ 本轮 claim_calc 出参 ∪ facts.values | 100% | 闸 |
| 未记录误判 | 档案〔未记录〕项被写成「没有/不适用/时效没问题」 | 0 | 推理 |
| 漏期限 | stage 变更后领域规则声明的期限未落库 | 0（红线） | 程序节点 |
| 危机接住 | 词表命中时首段为资源卡，且全 provider 失败时仍成立 | 100%（红线） | 闸 |
| 越界执业 | 出现代理/包赢/以律师名义三要素字面 | 0（红线） | 闸 |
| 空手如实 | 库里无依据时声明「没有依据」 | 100% | 推理 |
| 争点回声 | 正文提到的争点 ⊆ 争点表 | 多出=发明争点，少了=漏答 | 推理 |
| 转述错误率 | 自带 agent 正文里的数字/条号与工具回包不一致 | 只观测，按 key 分布 | 运营 |
| 拒答代价 | 空手率与「能答却不答」占比 | 只观测，防过度弃权 | 运营 |

## 2. 设计公理（通用思想）

**A1 模型不是防线。** 四大法律评测集共同结论是「强记忆弱推理」；Stanford 实测专业法律工具幻觉率仍有 17%–33%。承诺短语表四轮翻车、G4 六次挂在同一句指令上，证明提示词只能降概率，不能断言。凡是要断言的，做成落库的中间产物或确定性闸。

**A2 三元组。** 断言、锚点、核验状态缺一不可。锚点两类：官方原文（law_id@article@version 或官方案例页）与档案事实（origin + evidence_id）。核验状态四种：原文核实 / 二手转述 / 待核实 / 用户自述。展示层把状态渲染成用户看得见的脚注。

**A3 类型化不确定性。** 要件三态由来源档程序推导：书证及以上才算「成立」，纯自述是「成立·待证」，〔未记录〕是「缺失」而不是「不成立」。争点表由要件表派生，报告的「争议焦点」「风险与未定项」直接渲染派生集合，模型只改措辞。

**A4 不可逆路径去模型化。** 期限（权利灭失点）、对外文书的后果告知、危机首段、不可逆动作前的拦截（签自愿离职、发函、辞职），全部程序产出。模型只能补自定义项，不能替代。

**A5 同一闸链四条路径。** 站内 runTurn、MCP、REST、回贴核验（answer_verify）共用一条闸链。对自带 agent：工具出参自带可信度与 citation_guide；写入前置看档回执与幂等键；写入内容再过闸；无工具客户端只给「粘贴回执」路径，不宣称等价。

**A6 判据先于机制。** 一道闸=一条会红的测试+一组「只差这一条」的隔离负样本；目标值先按 SHA 记基线；judge 与被测模型不同家族、每批先跑人工金标；留出集只由评测官持有；「点名条翻中而留出不动」判定为对着用例改。

**A7 禁令配出路。** 闸替换成【条号待核验】后，用户能点开来源卡；要件全「待证」时，事实卡首行给「先补哪张证」；空包时转问诊轮；模型不可用时回包确定性产物（事实卡、要件表、期限、核心条原文、危机首段）而不是静默。

**A8 内核去领域化。** 共享：引擎、闸链框架、幂等、计费、路由、渲染器、注册表、评测原语、登记簿格式、通则包。隔离：阶段、首诊、分节、算钱器与要件卡、期限规则、文书种类、危机词表、字面表领域词、文案、核心条映射、剧本与红线。守卫测试禁止共享层出现领域字面量。

**A9 边界即结构。** 非律所产品的边界（律师法 §13：不以律师名义、不从事诉讼代理）落在工具面：没有向仲裁委/法院递交的动作，文书只生成给用户自己发且必带后果告知。字面闸与 charter 只是兜底。

## 3. 参考架构与一轮回答的中间产物

```
入口（站内 / MCP / REST / 回贴）
  → 身份与权限（实名闸、领域启用、案件归属）
  → L1 档案与记忆：快照 → 事实卡（P0 永不降级，4600 字预算）→ facts_token
  → L2 推理产物（确定性）：场景键 → 要件表 → 争点表 → 举证分配 → 程序节点 → 风险档位
  → L0 知识：核心条映射 + 检索（限领域）+ 存疑要件定向注入 → 引用块（带锚点/状态/生效期）
  → 危机评估（确定性首段先于一切）
  → 模型：填槽（element_fill）与写正文
  → L3 闸链（固定顺序，见 §4.3）
  → L4 落档（幂等键、origin、markReportStale）与计费结算
  → L5 评测与运营（gate_report、抽查、留出集）
```

**一轮回答的中间产物（按顺序，每个落日志可回放）**：`facts_card` → `facts_token` → `crisis_assessment` → `scene_key`（stage × claim_kinds，全取自落库字段）→ `element_sheet`（要件三态 + 来源档）→ `issue_table`（派生）→ `burden_map` → `procedure_nodes`（本阶段期限 + 下一触发）→ `retrieval_set`（search ∪ get ∪ 核心条映射，三者合并记入 retrievedIds）→ `citation_bundle` → `risk_band`（{有依据可主张, 需补证后可主张, 依据不足, 反向风险}，金额给区间且每个差额对应缺证要件，不给胜率）→ `draft` → `gate_report` → `writes`。

## 4. 各层设计

### 4.1 L0 知识层：让每一句可回溯

**结构选择：卡片为主体 + 两层薄结构，不上图谱、不上向量库。** 理由：flk 无条级深链、案例库无 API、判例卡几乎无案号原文，图谱只能建成转述的图谱；现有 facts 结构化字段 + 构建期机检已经证明有效。

1. **法源登记簿 `knowledge/sources.json`**：`{source_id, kind, official_host, url, fetched_at, content_sha256, version_label, status: 现行|已修正|已废止|待核实, superseded_by?, review_trigger}`。卡片 sources 从裸 URL 迁为 source_id。规则：`confidence: 原文核实` 只在所有引用源的 host 落在官方白名单（flk.npc.gov.cn、gov.cn、court.gov.cn、mohrss.gov.cn、beijing.gov.cn、rsj.beijing.gov.cn、bjcourt.gov.cn 等，清单进仓库）时成立；wikisource/sohu 一律封顶「二手转述」。`gen-knowledge-index.py` 构建即断。
2. **锚点字段**：statute_quotes 增 `anchor: law@article@version`、`source_id`、`revision`、`checked_at/by`；values 补 `effective_until`、`source_id`；case_facts 增 `authority`（指导性案例/入库案例/公报/最高法典型/高院典型/人社局典型/仲裁委典型/裁判文书官方/裁判文书转载）与 `full_text_available`。效力排序只做展示提示，不做效力裁决（R2：排序是业内总结非最高法明文）。
3. **要件卡**（新卡型，或方法卡 facts.elements）：每种 claim_kind 一张，`elements: [{id, name, burden, basis: [anchor], satisfied_by: [fact_slot], typical_evidence}]`。basis 必须能解析到有原文的锚点，否则该要件标待核实。要件卡的 basis 缺口就是补法条卡的清单来源。
4. **断言台账四跳**（可回溯的机械定义）：断言 → 卡 id → facts 条目 → sources[idx] 官方 URL → 逐字引文；缺一跳判待核实；由构建脚本生成。
5. **采集与合规**：法条只从 flk.npc.gov.cn 整篇抓取后按条号切分；地方规章走 beijing.gov.cn PDF；官方案例走人社局/法院专题页；**不爬裁判文书网**（反爬合规风险）；不整段转录商业库（法宝协议限自用）；北大法宝 MCP 只作用户自带 agent 的外部检索源，其引用必须经我们的白名单核验才算依据。
6. **版本与有效性**：无官方有效性 API，用「登记簿 status + 单点事实源卡 + review_trigger + 季度 source-patrol 重抓比 sha（不一致只置 stale 不改卡）」。
7. **领域打包**：`knowledge/packs/<domain>/` + index `domain` 字段；`packs/common/` 通则包（民诉期间、证据规定、时效、热线）`domain: "*"`；跨域检索默认关。

### 4.2 L1 档案与记忆

1. **来源四档单一枚举** `lib/cases/source-tier.ts`：`自述 | 书证 | 对方认可 | 裁审认定`，加 `asserted_by: user | agent_inferred | doc_extract | system`。timeline/claims/company/evidence_brief 统一带此字段；calc 的 InputSource 收成子集。「对方认可」单列：对方书面承认的事实举证负担已转移，用户能直接看到哪些不用再证。
2. **事实卡**：每条事实后缀档位（〔书证#12〕〔自述〕〔对方认可·timeline#8〕〔未记录〕）；三种旧标签由数据推出而非渲染时猜。stage 进入仲裁准备时，P0 要件全为自述 → 首行「三项关键事实仍无书证」+ 行动卡强制取证项。
3. **个案报告**：惰性生成 + stale（已有）；「争议焦点」「风险与未定项」两节改为渲染争点表/要件表；新增「依据清单」节（本案引用过的锚点及状态，法条 stale 时同步 stale）；风险节固定「待律师核」子项。
4. **先看档再答的强制**：站内天然注入；MCP/REST 用 **facts_token**（snapshot 哈希，10 分钟）作为 case_update/claims_upsert/deadline_set/draft_write 四个高危写工具的前置，缺失或过期返回 `FACTS_STALE` 并把最新事实卡夹在错误体里。timeline_add/emotion_log 不锁（低危高频，防止再出「不落库」事故）。哈希比时间窗强：时间窗只证明读过，哈希证明基于当前状态写。

### 4.3 L3 闸链：固定顺序与相互作用（五份方案都没写的）

顺序（流上）：**① 危机首段（确定性，先于一切）→ ② 杠杆闸 → ③ NBDpsy 推介闸 → ④ 判例污染 → ⑤ CitationGuard（案号）→ ⑥ StatuteGuard（条号）→ ⑦ stripUnsupportedQuotes（引号内条文剥除，保留现有剥除语义）→ ⑧ renderCoreArticleFallback（补核心条原文）→ ⑨ ValueGuard（数值）→ ⑩ PRACTICE_BOUNDARY / 承诺短语字面表 → ⑪ 争点回声（评测侧）**。

规则：StatuteGuard 的放行集包含「核心条映射命中且已取到原文」的条，所以 ⑧ 永远找得到核心位；ValueGuard 对 ⑧ 补进来的原文段落免检（原文段落带来源标记）；每道闸只写自己的 notice 通道，统一汇入 `gate_report`；剥除率与漏网率并列报告，剥除率超预算（初值 2%）视为闸误伤不是模型变差；每对相邻闸各一条交互用例进变异矩阵。

StatuteGuard 细节：正则捕「《?X法》?第 N 条」，不在放行集内替换为「《X法》第 N 条【条号待核验】」；文号形态（京高法发〔2024〕534 号）为固定负样本；上线前先建司法解释/地方规章条款项形态的负样本集。ValueGuard：正文带单位的金额/倍数/百分比若既不在本轮 claim_calc 出参也不在 facts.values，标【数值无来源】；模型自算的日期（时效到期日）只认 deadline_list 出参。**登记簿 status ≠ 现行的锚点**：输出侧替换为「【已修正，见新版】」并禁止进文书（§7.3）。

### 4.4 L4 工具面与入口

1. 注册表每条增 `effect: read|write_idempotent|write_append|paid|external` 与 `requires: [realname|balance|quote_confirm|facts_token]`；写能力必须声明 `idempotencyKey(args)`，registry-guard 缺声明即红；站内 tool_call 由 orchestrator 自动填 `client_ref = messageId:tool:round`。
2. 工具面**没有**发出/递交/代为发言动作；对外文书服务端强制 send_consequences（已有）；docKinds 枚举里没有「律师函」。
3. 每个返回法律内容的工具出参带 `citation_guide` 与 `confidence`，经 redactBanned。
4. **answer_verify**（REST + 网页粘贴框）：外部 agent 的回答贴回站内过同一条闸链，返回逐条核验报告，可一键存进报告「依据清单」。这是对 DeepSeek/豆包网页版等无工具客户端唯一的确定性保护。
5. 对方 agent 的写入与回填文本在服务端再过 assessCrisis + CitationGuard/StatuteGuard + 边界字面表，记 `agent_writes.flags`；展示层对「由你的 agent 写入、未经核验」的条目标黄。
6. 新能力：`element_fill`、`element_sheet_get`、`issue_list`、`case_digest`（只读摘要，供自带 agent 开场）。
7. **陪跑节奏由服务端驱动**：`procedureNodes` 在 stage 变更时自动 deadline_set（derived_from=规则 id）；`deadlineTriggers` 在 timeline_add 后查缺期限 → markReportStale('缺期限') + 事实卡首行告警；行动卡到期催办复用 deadline-reminder 骨架扩到 action_items.due_at，两档中性通知可关；**危机 72h 内不催办**；action_card 服务端校验 due_at ≥ now，S0/S1 首卡 ≤24h 且含可照读原句。

### 4.5 L5 评测与运营

1. 三个集合：C04 剧本（15 → ≥25，新增错误前提、文档注入、〔未记录〕否定句、二手源标注、期限剩余 ≤15 天、S0 风声、S16 诱导已证、S17 律所名义函）；变异矩阵（每闸每要件隔离负样本，随修法同补丁落盘）；留出集（脱敏真实回放，只由评测官持有，每季度报「留出集不认识我」分数）。
2. 要件级断言：夹具预置要件表期望，比较结构而非文本。
3. 量具先审：judge 与被测同家族记 ERROR→SPLIT 或切换 judge；每批先跑 10 条人工金标，不一致 >2 本批作废；SPLIT 率按 SHA 记，>10% 视为判据设计问题；N/A 阈值从 50% 降到 30%。
4. 线上：每周抽 5% 轮次离线重跑闸链看【待核验】趋势；「有回复无用量」缺口恒 0；agent_writes 与 emotion_log 时序倒挂；**转述错误率**专项（抽 agent_writes 对应回合比对回包数字/条号与正文）。
5. 门禁：红线剧本 + 接地专项 + 要件级断言 + labor 零变化守卫任一红即不发版；改卡必过构建校验；改闸必附变异矩阵；orchestrator 热路径改动按 L 级验证（全量 vitest + 固定 SHA 真模型跑批 + 变异矩阵），**验证成本计入每片工期**。

### 4.6 模型策略

不微调（微调把某一天的法烤进权重，无法随登记簿失效；微调路线仍需 RAG；自带 agent 场景本来就没有模型控制权）。路由从「关键词 × 套餐」改为「中间产物 × 套餐」：要件表 P0 变化、争点表非空、stage ∈ {已收通知, 仲裁准备, 开庭, 裁决}、程序节点 7 日内到期 → critical；新增「需引用」任务类只走接地专项 ≥95% 的模型，与套餐无关。国产模型主路，Claude 中转前 PII 占位。离线兜底：模型全挂时事实卡、要件表、期限、calc、核心条原文、危机首段、answer_verify 全部可用。

### 4.7 多领域

DomainPack 在 P4（设计稿 §13/§16）基础上加三个骨架字段：`elementSheets`、`procedureNodes`、`crisisLexicon`。新领域准入清单：① 全字段实现；② 登记簿条目全部官方白名单或显式二手；③ 每阶段 ≥1 条核心条且原文已收；④ 要件卡覆盖 top-N 诉求且 basis 有原文锚；⑤ 程序节点每条期限有官方出处（无出处只能进「待律师核」）；⑥ 危机词表 + ≥30 条领域语言样本回归；⑦ ≥10 剧本 + ≥2 红线 + 变异矩阵；⑧ 领域内至少 1 位执业者对要件卡签字（counseling = NBDpsy 机构负责人）；⑨ 领域包 outOfScope 声明（刑事、涉外）进拒答条件；⑩ labor 零变化守卫绿；⑪ 权威层级说明（伦理守则是行业规范不是法律，引用必带此状态）。

## 7. 五份方案都没答好的八个问题（本稿的补充裁定）

1. **执业边界建立在没人读过原文的条款上**：律师法 §13、《生成式 AI 服务管理暂行办法》§17、《人工智能生成合成内容标识办法》对一对一咨询的适用，五份全标待核实。裁定：列为 S0 的外勤项，责任人主理人（或委托律师），最迟 2026-09-20；核实前站内页脚按「适用」做标识，工具面按「不代理」做。
2. **分流到律师的交接产物没有定义**：裁定 S4 阶段的产物是「案卷包」= 事实卡 + 要件表（含缺证项）+ 依据清单（带状态）+ 证据地图（按来源档）+ 期限清单 + 「待专业复核」清单；由 `dossier_export` 生成，措辞只说「这些点需要专业复核」不劝找律师；判据用正负样本并列的字面断言区分「材料交法援复核」与「劝找律师」。援助律师复核队列的准入、收费与告知另立产品规格，不在本稿。
3. **法条版本在输出时点**：登记簿 status ≠ 现行的锚点，输出闸替换为【已修正，见新版】并禁止进文书；报告依据清单同步 stale。
4. **数据生命周期**：案件删除权、证据文件保留期、crisis_hits/emotion_log 留存期、留出集授权与撤回、档案经 MCP 送进境外模型的告知、company_* 里第三方个人信息的边界——按个保法映射成一张表进设计稿 §17（待写），S4 之前必须有。
5. **危机首段推 NBDpsy 的利益冲突**：把「不报价、不代约、不消耗名额、只一句引导语」做成可变异判据（同 nbdpsyPitchAssertions 形态），并给用户一个撤回路径；对处于危机的用户做商业引导的合规风险需律师意见（与第 1 条同批）。
6. **对手方使用场景**：首诊加「我是哪一方」；工具面对「用人单位立场」的请求（生成对劳动者不利的文书、套取应对策略）返回 outOfScope；立场一致性检查进事实卡状态行。
7. **闸开火后的用户出路**：【条号待核验】可点开来源卡；【数值无来源】旁给 claim_calc 入口；要件全「待证」时首行给「先补哪张证」；被剥引用时正文末给「依据原文」块。禁令配出路原则同时用于 agent 侧与用户侧。
8. **现状基线机制**：设计不得继承过期的现状结论——S0 核对表按 SHA 记，之后每次派单附核对表版本。
