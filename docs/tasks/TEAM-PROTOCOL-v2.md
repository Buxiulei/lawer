# 团队协作制度 v2（2026-08-21，因"调研员卡死一天未被发现"事故重立）

## 一、编制（7 个会话，各一条命）
| 会话 | 职责 | 边界 |
|---|---|---|
| manager | 总控:架构/派单/裁决/PR终审/对外唯一接口 | 不写业务代码 |
| **哨兵**(新) | 专职监工:每15分钟巡逻一轮（见监控流） | 无业务上下文,只看不改,轻量防撞限 |
| **评测官**(新) | 红线/C04/C07 评测循环、judge 复核、证据产物管理 | 只评不改产品代码;修复归 WS2 |

| 前端页面 | UI/主题/图谱 | 不碰 src/lib |
| **外勤**(执行者转型) | 用户案的"手活":gsxt/文书网交互取数、验证码接力、周检执行、监控运维 | 知识库维护保留;研究归调研员 |
| 调研员 | 纯研究与情报分析(法律口径/数据源/评测集) | 交互式取数移交外勤 |
| 援助律师 | 用户案件全权对接 | 需求经 manager 派单 |

## 二、心跳文件制（进度的唯一真相）
- 每会话领卡开工即写 `docs/tasks/heartbeats/<角色>.txt`（仓库不提交,本地即可）:每完成一步追加一行 `时间戳|当前步骤|状态(干活中/等外部/等用户/卡住/撞限暂停)`。
- **"等用户/等外部"是合法状态**,写明等什么——哨兵不把它算卡死。
- 撞限前必写 `撞限暂停|恢复点=X`,恢复后先读自己心跳与 BOARD 再续。

## 三、汇报流（三级,减少噪音）
1. 例行进展 → 只写心跳文件+BOARD 自己行**不发消息**（BOARD 由 manager 汇总维护,汇报三件套照旧格式写心跳）。
2. 交付/裁决/卡点 → SendMessage manager。**卡点即产出:卡住 15 分钟内必须报卡点,"卡住不报"=纪律事故**。
3. 紧急（生产事故/用户案 urgent）→ SendMessage manager+援助律师双发。

## 四、监控流（三层兜底）
1. **哨兵每 15 分钟巡逻**（自跑 /loop）:①心跳文件 mtime 对账（干活中状态却 >30min 无更新→嫌疑）②tmux capture-pane 抽查嫌疑会话屏幕（卡在空提示符/待确认弹窗/error=卡死）③用户案监控自检（timer/proxy/discovery state/ALERT 新文件）④异常→SendMessage 叫醒当事会话,两轮(30min)无效→报 manager。
2. **manager 每次被唤醒**顺手核关键路径文件 mtime（不等汇报）。
3. 用户案自身的邮件+短信告警照旧。

## 五、任务卡标准（manager 派单自律）
必含:目标/验收标准/下次汇报≤X 时限/卡住怎么办（降级路径）。超 2X 静默由哨兵触发探查。
