## 二、心跳文件制（进度的唯一真相）
- 每会话领卡开工即写 `docs/tasks/heartbeats/<角色>.txt`（仓库不提交,本地即可）:每完成一步追加一行 `时间戳|当前步骤|状态(干活中/等外部/等用户/卡住/撞限暂停)`。
- **状态词白名单（2026-08-28 公开）**——`时间戳|状态|内容` 的**第 2 栏**决定探针用哪档停更阈值：
  - **宽档（4 小时才判停更）：`待命` / `等外部` / `等用户`** —— 仅此三词。
  - **严档（45 分钟即判停更）：以上之外的一切**，包括常被写的 `在岗` / `在办` / `干活中` / `空闲` / `在线` / `收工`。
  - **匹配是前缀匹配**：`待命(团队暂停期例外岗)`、`等外部(等验证码接力)` 都落宽档，
    **说明等什么不必牺牲档位**。（此前只有代码里有这条，没人公开过。）
  - 取不到第 2 栏时记 `STATUS_UNPARSED` 并**按最严的判**。
  - **为什么必须公开**：词表不公开时，这条判据量的是"猜没猜中词"而不是状态。
    后台技术整天写 `在线`/`空闲` 挂严档，而他的真实状态恰是 `等外部`+`等用户`——
    **他够得着这条判据，只是够不着它的词表**；13:09 他写 `空闲` 是他能给的最准确的词，
    却因不在表里落严档，**说得越准罚得越狠**。词表一贴，15:01 那条即改写为 `等用户`，误报当场消失。
  - **未知词默认严档是有意的**（默认宽会让任何笔误买到 4 小时免检）；
    `收工` 与 `撞限暂停` 被**刻意排除**——能让当事人自己买到免检的词不进白名单。
  - **改词表＝改判据**，须经 manager 并征审被影响岗，不要自行增删。
- ~~撞限前必写 `撞限暂停|恢复点=X`~~ **（2026-08-27 改）**：「撞限暂停」已从探针白名单删除——全部心跳里它用过 0 次，且一旦被用是后门（预警只说"可能要撞"，写下它就买到 4h 免检）。**改为：收到 `[Usage limit approaching]` 做 checkpoint 时，checkpoint 动作本身必须包含写一条心跳**（状态按当时真实状态写：在岗/待命/等外部，**不写撞限**），恢复后先读自己心跳与 BOARD 再续。理由：撞限是注意力问题不是能力问题（那一刻能写，只是没人想起）；把写心跳并进 checkpoint 这个动作，是唯一能力级的解法。

## 三、汇报流（三级,减少噪音）
1. 例行进展 → 只写心跳文件+BOARD 自己行**不发消息**（BOARD 由 manager 汇总维护,汇报三件套照旧格式写心跳）。
2. 交付/裁决/卡点 → SendMessage manager。**卡点即产出:卡住 15 分钟内必须报卡点,"卡住不报"=纪律事故**。
3. 紧急（生产事故/用户案 urgent）→ SendMessage manager+援助律师双发。

## 四、监控流（三层兜底）
1. **哨兵每 15 分钟巡逻**（自跑 /loop）:①心跳文件 mtime 对账（干活中状态却 >30min 无更新→嫌疑）②tmux capture-pane 抽查嫌疑会话屏幕（卡在空提示符/待确认弹窗/error=卡死）③用户案监控自检（timer/proxy/discovery state/ALERT 新文件）④异常→SendMessage 叫醒当事会话,两轮(30min)无效→报 manager。
2. **manager 每次被唤醒**顺手核关键路径文件 mtime（不等汇报）。
2b. **限额重置唤醒制（2026-08-21 增，哨兵第4轮发现的盲区）**：撞限会话**不会自己恢复工作**——哨兵巡逻见屏幕停在 limit 提示即记录"会话+最后活动时间+屏幕摘要"，主动向 manager 发「限额恢复唤醒清单」；manager 逐个 SendMessage 唤醒并**下发恢复点**（该会话该续做什么、依赖是否已就绪）。哨兵只发现上报、不代唤醒（唤醒须带恢复点，属 manager 职责）。
3. 用户案自身的邮件+短信告警照旧。


4. **进程内子代理不算盯梢（2026-08-25 增，WS2 停摆事故）**：主会话悬停（撞限/弹窗/挂死）连带其进程内子代理全哑——**进程内子代理与主会话同生死，不能作为主会话自身故障的对冲**；对冲该失效模式的只有跨会话独立盯梢（哨兵/评测官形态）。据此：①各会话把"派子代理盯 X"理解为盯 X 的故障，不盯自己的故障；②哨兵巡逻对"心跳停更 + tmux 屏幕悬停"的会话，默认其子代理已一并失效，不等子代理上报。
   > 实例：08-23~25 WS2 主会话撞限+弹窗悬停约 1.5 天，进程内双代理同刻停摆，"卡住 15 分钟必报"因会话本体失去执行权而失效，靠跨会话（manager）发现接管。


5. **离线测量必须在可指名 SHA 的快照上做（2026-08-25 增）**：不得在活动工作树上量数——**活树是别人的施工现场，在里面量出的数不属于任何版本**，同一探针可能两次不同结果。做法：`git archive <SHA>` 取只读副本 + sha256 逐字节核对 + 连跑稳定性验证。与"批跑期间双冻"同族，但覆盖"单人量数"这个更常见的场景。

**跨项目错投（2026-08-27 增，后台技术上报）**：本机同时跑 NBDpsy 与 lawer 两组会话，**会话名可能只差一个字**（NBDpsy `后台` / lawer `后台技术`），分属不同 tmux 组，**`SendMessage` 发错不报错**。当天一份契约（咨询师名片渠道码，含印出去就改不了的小程序页面路径）被发到了 lawer 的后台技术。收件方处置：核实路径不在本仓、退回、指正确地址、**不替对方猜任何字段**。
**规矩**：契约级 / 印刷级 / 不可逆事项，发出前先 `ListAgents` 确认收件人对得上哪个仓。**一个不报错的错投，最坏的结局不是没人收到，是有人收到了并且照办。**

必含:目标/验收标准/下次汇报≤X 时限/卡住怎么办（降级路径）。超 2X 静默由哨兵触发探查。

## 六、模型使用策略（2026-08-21 用户拍板：按能力诉求定档，禁止高档模型干低档活）
总原则：**子代理默认继承主会话模型——凡"盯/读/搬运"类循环任务必须显式降档；凡"钱/证据/法律结论"类必须 Opus 及以上**。

> **2026-08-23 修订（用户拍板）：Fable 额度耗尽，全线主会话改用 Opus。**
> 影响：①原"Fable 档判断力"承担的设计/裁决/终审工作由 Opus 承担，标准不降；
> ②降档规则不变（巡逻/机械核对 = Haiku，阅读/识图/视觉核对 = Sonnet，代码执行 = Opus）；
> ③**Opus 既是主会话档也是执行档，故"降档干活不降档拍板"的边界改为"子代理干活、主会话拍板"**——
> 同档不同角色，产出仍须主会话复核后才算数，不因同档而省略复核。
| 角色 | 主会话干什么 | 子代理降档规则 |
|---|---|---|
| manager | 设计/裁决/终审（Fable） | 探查类派 Sonnet,机械核对派 Haiku |
| 哨兵 | 只做异常判断与上报 | **每轮巡逻派 Haiku 子代理**执行(mtime 对账/capture-pane 摘要/timer 自检),主会话只读摘要,正常轮零高档消耗 |
| 评测官 | 跑批编排/成绩单/终审材料 | judge 转录阅读与 SPLIT 初审归纳=**Sonnet**;批量日志比对=Haiku |
| 后台技术 | 设计/自审 | 写代码执行=**Opus**(现行不变);日志/文档大批阅读=Sonnet |
| 数据表管理 | 设计/审计 | 同上:执行 Opus |
| 前端页面 | 设计/验收 | 代码=Opus;**截图视觉核对/页面元素理解=Sonnet** |
| 外勤 | 流程编排/风险判断 | **验证码识图与页面元素理解=Sonnet**;批量抓取解析/格式搬运=Haiku;涉证据固化操作=主会话亲自 |
| 调研员 | 综合分析/定性结论 | 大批网页阅读提炼=**Sonnet**;法条判例逐字核验=**Opus**(零容错) |
| 援助律师 | 用户对话全程主会话(质量敏感,不降档) | 大文档/长录音转写阅读=Sonnet |
红线:①法律结论、金额计算、证据操作、给用户的最终话术——**永不交给 Haiku**;②巡逻/轮询/心跳类——**永不用主会话高档模型空转**;③子代理产出回主会话复核后才算数(降档干活,不降档拍板)。
## 手动操作留痕（2026-08-29 立，discovery-state 事件）
**手动触碰生产状态文件/生产数据的任何操作，必须当场留痕**——一行心跳或操作日志即可（格式：`HH:MM 手动跑了 X，为了 Y`）。事由：一次正当的手动验证运行因未留痕，制造了一个需要六源互证才能解释的"异常"——它本可以是一行字。配套：监控判据应自述盲区（如「本判据看不见手动调用」）；结论措辞用「systemd 之外的写入」而非「运行以外的写入」。
