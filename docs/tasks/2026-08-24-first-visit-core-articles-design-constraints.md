# 首诊核心条来源·专议设计约束（manager 备忘，专议输入件）

> 背景：⭐核心条机制取料于档案三来源（claims.basis / 行动卡 detail / deadlines.derived_from），
> 首诊时三来源全空 → ⭐段整段不输出。而首诊恰是用户最没判断力、最需要正确引用的时刻。
> 教训原句：「不猜 ≠ 什么都不给」「克制到用户拿不到东西就是缺席」。

## 约束清单（方案必须逐条满足或显式说明为何不适用）

1. **指引可溯源**：首诊指引的"场景→核心条"映射必须是**结构化数据**（知识卡），
   不是模型自由发挥——否则等于把第五闸拆了重新引入编造风险。
2. **映射表走既有管线**：映射卡入 knowledge packs、过同一校验器、代码只读结构化字段
   （"代码不啃散文"铁律的延伸，不另起一套加载机制）。
3. **两模式切换判定同源**：首诊模式（场景映射）↔ 档案模式（三来源）的切换判定
   = "三来源是否为空"这一结构化事实，**产线与判据 import 同一判定函数**
   ——判据侧已按此落（首诊 G4 按⭐机制不可用处理），行为侧必须用同一把尺。
4. **评测同步重定义**：新机制落地后，S03 首诊场景的 G4 预期改为
   "⭐应出现，内容 = 场景映射的核心条"；映射卡错 → 账记知识库，不记模型。
5. **YAGNI**：第一版映射只覆盖 15 剧本对应的场景族（解除/欠薪/协商/危机等），
   不做全场景枚举；覆盖不到的场景族显式回落"无⭐段"（现状），不硬凑。
6. **别过度指引**：首诊映射给的是"该场景族的高频核心条"，注入侧仍标注来源与适用前提；
   agent 话术保持"初步方向、待细化"口径——首诊的克制保留在**表达层**，不再体现为**缺席**。

## 专议流程

ws2 带方案 → 对照本清单逐条过 → 定映射卡 schema 与首批覆盖面（WS4 编卡）→ 行为修 → 重跑。
