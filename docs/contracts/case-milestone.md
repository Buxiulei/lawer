## 一、问题

驾驶舱要渲染「里程碑时间轴，完成/进行中/未到 三态，**允许回退**」。
现有类型里**没有里程碑模型**。两个相邻的东西都不够：

| 现有 | 是什么 | 为什么不够 |
|---|---|---|
| `CaseRecord.stage`（12 值枚举） | 单值**当前态** | 没有历史。只知道现在在哪，不知道哪些走过、什么时候走过 |
| `TimelineEvent`（事件日志） | 有历史、有时间戳 | **没有阶段归属**，也没有三态。它是流水账，不是里程碑 |

后台技术补充的第三条事实，比上面两条都硬：

```
timeline_events.kind = 公司动作 | 我方动作 | 系统动作 | 期限   ← 行为主体轴
CaseMilestone        = 协商 | 仲裁申请 | 立案 | …             ← 进度轴
```

**四个主体值到八个里程碑之间不存在函数。**「立案」算我方动作还是系统动作？都说得通。
承载信号的只有 `title`/`detail` 自由文本。
⇒ `milestone` 是**承重字段，不是便利字段**：没有它，任何东西都推不出里程碑。

## 二、核心结论：三态不能从 `stage` 标量推

这条是「回退」逼出来的，不是风格偏好：

产品方案写「允许回退（谈崩重回仲裁不算倒退，**时间轴如实记**）」。
若三态 ＝ 拿 `stage` 序号和阶段序号比大小，那么 stage 从「已立案」退回「仲裁准备」的那一刻，
「立案」会从 `完成` 翻回 `未到` —— **立案那天确实发生过，这个事实被抹掉了**。
跟产品方案第贰条骂线性进度条失真，是同一条罪。

→ **三态必须从只追加的事件流推**：某里程碑有达成事件 ＝ 完成（带日期）；
回退 ＝ 再追加一条新事件，旧的完成**不动**。

## 三、类型增量

**为什么不用 `CaseStage` 的字面量子集**（这是 manager 裁定②的原方案，被后台技术实测驳回，
manager 已认）：`Extract` **fails open**。后台技术在本仓 tsc `--strict` 下实测——
若有人把 `CaseStage` 里的 `已立案` 改名，`Extract<CaseStage, … | '已立案' | …>`
**一句话都不报，退出码 0**，`CaseMilestone` 悄悄少一员。
⇒ 一个专门用来防词表静默漂移的机制，**自己的失效方式就是静默漂移**。

改用**独立联合 + 全量对照表**，两个方向都会红。

**我自己复现了一遍**（没照转述走——这是契约里的承重论据）：同一台 `tsc --strict`，
把 `CaseStage` 的 `已立案` 改名成 `立案已受理` 这一个动作——

| 写法 | 结果 |
|---|---|
| `Extract<CaseStage, … '已立案' …>` | **退出码 0，一句话不报**。`CaseMilestone` 静默少一员 |
| `Record<CaseStage, CaseMilestone \| null>` | **退出码 2**：`error TS2353: … '已立案' does not exist in type 'Record<CaseStage, …>'` |


```ts
export type CaseMilestone =
  | '协商' | '仲裁申请' | '立案' | '开庭' | '裁决' | '一审' | '二审' | '执行';

/**
 * CaseStage → 它属于哪个里程碑。**全量**：Record 的键覆盖 CaseStage 每一个值。
 * 新增或改名任一 CaseStage 值，此处不补即编译失败（TS2741 / 多余键报错）；
 * 把 `已立案` 这类 stage 词误当里程碑写进来，也是编译失败（TS2322）。
 */
export const MILESTONE_OF_STAGE: Record<CaseStage, CaseMilestone | null> = {
  风声: null,      // 还没进入任何里程碑
  约谈中: '协商',
  已收通知: '协商',
  已解除: '协商',
  仲裁准备: '仲裁申请',
  已立案: '立案',
  开庭: '开庭',
  裁决: '裁决',
  一审: '一审',
  二审: '二审',
  执行: '执行',
  结案: null,      // 轨道末格已达成，不再是「当前里程碑」
};

export interface TimelineEvent {
  // …现有字段全部不动…
  /** 置上表示这条事件构成「达成该里程碑」。驾驶舱时间轴只读有此字段的事件。 */
  milestone?: CaseMilestone;
}

export interface CaseRecord {
  // …现有字段全部不动…
  /** 该案的里程碑轨道，有序。仲裁轨默认前五个；进入诉讼后由后端追加。 */
  milestones: CaseMilestone[];
}
```

**没有展示名映射层**：键即显示名。少一层映射，少一处会漂的东西。

**轨道必须可变长**：`CaseStage` 里躺着 `一审/二审/执行`，五格写死表达不了；
案子进了法院，驾驶舱该长出后面的格子，而不是永远停在「裁决 完成」。
（落地页卷二第五步同一天补上「起诉或应诉，都接着排」，说的是同一件事。）

### 三·附：一段被消解掉的两难，记在这里防止有人重提

本稿早先版本按「`CaseMilestone` ⊆ `CaseStage`」写过一稿，撞上一个死结：
**第一格「协商」在 `CaseStage` 里没有对应值**（那段被拆成 `风声/约谈中/已收通知/已解除`
四个更细的值，没有一个表示整段）。当时的三条路都要付代价——
用 `约谈中` 当键会让「公司不谈直接解除」的案子在库里留下一条从没发生过的约谈；
用 `已解除` 会让**在职期间讨薪**的案子第一格永远达不成、整条轨道卡死；
给 `CaseStage` 加 `协商` 则等于把要消灭的近义词表换个地方长出来。

改成独立联合后，**这三条代价一条都不用付**：`协商` 只存在于 milestone 域，
`cases.stage` 一个字不动。

后台技术那句总结值得留着：**代价是「子集」这个约束强加的，不是问题本身固有的**。
更根上的理由是它和第二节打架——第二节刚把「只追加的既成事实」和「可变可回退的当前态」
拆成两种东西，子集约束又要求前者 ⊆ 后者，**把刚拆开的两样重新绑回去**。

## 四、写入授权表（契约的主体）

manager 裁定①：两轴之间无函数 ⇒ 每个 milestone 必须逐格写明**谁提议、谁确认**；
这张表升格为契约主体，不是附录。

**产品理由（manager 原话口径）**：milestone 是只追加、不可撤销的事实断言，
**不可撤销的写入不许由启发式产生**——抽错一次就永久多一格，而按定义没有撤销语义
（有撤销就回到「能被抹掉」，整个设计白做）。
这与决定权交还是同一条魂：**案件史归用户执笔，agent 只递笔。**

⇒ **全部八格一律「agent 提议 + 用户一键确认」，或用户主动标记。没有任何一格由规则自动写入。**

| 里程碑 | 触发情形（agent 何时递笔） | 提议方 | 确认方式 |
|---|---|---|---|
| `协商` | 用户上传或录入解除通知书、协商协议，或对话中确认谈判已终止 | agent | 一键确认「协商这一段结束了」 |
| `仲裁申请` | 仲裁申请书状态转「已发出」，或用户上传递交凭证 / EMS 单号 | agent | 一键确认「已经递交」 |
| `立案` | 用户上传受理通知书（OCR 命中「受理」+ 案号） | agent | 一键确认 + 校对案号 |
| `开庭` | 开庭期限到期后首次进入应用，或用户上传开庭笔录 | agent | 一键确认「已经开过庭」 |
| `裁决` | 用户上传裁决书 | agent | 一键确认 + 校对裁决日期（起诉 15 日期限由此起算） |
| `一审` | **两向都算**：①用户决定起诉并递交起诉状；②**收到公司起诉状副本**——被动进入诉讼也是里程碑 | agent | 一键确认（②的措辞是「公司起诉了，你是被告」，不是「你起诉了」） |
| `二审` | **两向都算**：①用户上诉；②**收到公司上诉状副本** | agent | 一键确认 |
| `执行` | 用户上传到账凭证或终结本次执行裁定 | agent | 一键确认 |

**兜底**：以上触发全部未命中时，用户可在时间轴上**主动标记**任一里程碑达成。
这条不是补丁——它是「案件史归用户执笔」这句话的落地形式，没有它，
一个走了非典型流程的人就只能眼看着轨道停在错的地方。

**跳过的处理**：某阶段被跳过时判定不改——公司不谈直接解除，
「收到解除通知」照样把 `协商` 记为达成。**跳过不是没发生，是以另一种方式结束了。**

## 五、三态推导（前端做，写在这里是为了两边口径一致）

```
events  = 该案所有带 milestone 的事件，按 happenedAt 升序
last    = events 的最后一条

进行中：
  events 为空                       → 轨道第一格
  last.milestone 在更早事件里出现过   → last.milestone 本身（这是回退信号）
  否则                               → 轨道上 last.milestone 的下一格
                                      （没有下一格 ＝ 全程走完，无进行中）

完成：有达成事件、且不是「进行中」那一格。日期取该里程碑**最早**那条事件
跳过：自己没有达成事件，但轨道上它**后面**有 → 渲染成完成，**但不带日期**（灰点）
未到：自己没有达成事件，后面也没有
```

**为什么用「最新事件」而不是「第一个没有事件的格」**：后者在真回退上会算错。
例：撤回仲裁申请退回协商——此时「仲裁申请」「立案」都**确实发生过**，事件不能删（如实记），
按「第一个没事件的格」会把进行中算到「开庭」，而案子其实回到了谈判桌。
按最新事件算，进行中回到协商，而仲裁申请/立案保持完成带原日期——
**轨道上同时出现「前面进行中、后面已完成」，这不是渲染 bug，这就是回退的诚实样子。**

**为什么「跳过」要和「未到」分开**（这条是我自己复查时发现的洞，不在原稿里）：
两者都是「自己没有达成事件」。若合并，跳过的格会渲染成「未到」，
于是轨道上出现「未到的格后面跟着已完成的格」——**和回退长得一模一样**，用户分不出
「这段我没走」和「我退回来了」。分开之后，跳过是灰点无日期，回退是前格高亮，两者不再同形。

## 六、持久层（manager 裁定③④：这是真契约，不是渲染形状）

- `timeline_events` **加 `milestone` 列**。后台技术已核：`migrate.ts:12-16` 已有
  `PRAGMA table_info` 判断后再 `ALTER` 的幂等封装，加列可重跑自愈，
  **不绑今天刚定的迁移事务化那条线**。
- `CaseRecord.milestones` **存**，不现算。
  理由（后台技术无反对）：现算等于把「这案子走哪条轨」的判断藏进推导函数，一审那条分叉会推错。
- **取值域用测试钉死，不能只靠 TS 类型**——类型在运行时不存在，写进库的是字符串。
  存 JSON 数组时 CHECK 管不到内容。
- CHECK 约束并进数据表管理那笔递延，事务化后一起上。
- **未知值必须响，不许静默**：读到不在枚举里的 `milestone`，
  前端 `console.warn` 后忽略该事件，不静默当成没有。
  （同一课在 `_stream/frames.ts` 的 `CALC_FAILED` 上付过一次学费：
  一个空串被 `if (!copy) return null` 吞掉，页面照常渲染、无异常信号。）

### 六·二 「无确认不写」怎么落（manager 2026-08-28 二次裁定，采后台技术版本）

第四节那句「零自动写入」若只写在纸上，就只是一条纪律。落法改为**结构性**的：

- `insertTimelineEvent`（通用写路径）**不接受 `milestone` 参数**。
  通用路径在类型上就设不了这个字段，「绕过」从纪律问题变成**没有入口**。
- 另开**唯一写点** `confirmMilestone`，签名里**要求确认凭据**（用户确认动作的凭证）。
  全仓触碰 milestone 列的 SQL 只应存在于这一处。

守卫写成**三条正向断言**（不是「找不到即绿」的否定式存在断言——
那族测试在实现被删光时会变绿，等于没守）：

| # | 断言 | 断言的是 |
|---|---|---|
| a | 走通用写路径落库后，该行 `milestone` **恒为 NULL** | 运行时真的设不上，不是靠类型 |
| b | 调 `confirmMilestone` 缺确认凭据 → **400** | 唯一写点自己也拦 |
| c | `lib/db/cases.ts` 中**写**（`INSERT`/`UPDATE`）milestone 列的 SQL 语句数 **`toBe(1)`**（不是 `≤1`） | 多一条＝有人另开了后门；**少一条＝实现被删光，同样红** |

**判据（一句话原则，本项目通用）**：

> **要么把禁令变成结构上做不到，要么让守卫在自己被删掉时也会红。**

**「写」这个限定词是落地时挣来的，不是一开始就有**：原稿写的是「**触碰** milestone 列」，
后台技术照字面实现时发现它**恒为 2、永远红**——`listTimelineEvents` 的 `SELECT` 也正当地
触碰该列，那是读透传不是后门。措辞问题，不是判据问题：精确计数、两个方向都红，一个没变。
记在这里是因为**下一个照纸实现的人会撞同一堵墙**。

`toBe(1)` 与 `≤1` 的差别就是这条原则的全部：`≤1` 在实现被整段删掉时是绿的，
它同时容忍「零个」和「一个」，而「零个」意味着这条契约根本没被实现。

后台技术跑变异矩阵时把这句话变成了一条跑出来的断言：变异 M4「唯一写点整段删光」，
守卫 c 报 `expected [] to have a length of 1 but got +0`——`≤1` 会放过它。

**还有一条从那次矩阵里长出来的通用纪律，一并入纸**：

> 跑完变异矩阵，回头问一句——**哪条守卫从头到尾没有被任何一条变异钉红过？**

没被钉红的守卫，牙是没被证明的，它只是碰巧和别的守卫并存。
后台技术前四条变异跑完发现守卫 a 一次没红，补了第五条（把后门一路开到领域层透传）才让它红。
