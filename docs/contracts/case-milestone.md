## 一、问题

驾驶舱要渲染「五阶段里程碑时间轴，完成/进行中/未到 三态，**允许回退**」。
现有类型里**没有里程碑模型**。有两个相邻的东西，都不够：

| 现有 | 是什么 | 为什么不够 |
|---|---|---|
| `CaseRecord.stage`（12 值枚举） | 单值**当前态** | 没有历史。只知道现在在哪，不知道哪些走过、什么时候走过 |
| `TimelineEvent`（事件日志） | 有历史、有时间戳 | **没有阶段归属**，也没有三态。它是流水账，不是里程碑 |

## 二、核心结论：三态不能从 `stage` 标量推

这条是「回退」那个要求逼出来的，不是风格偏好：

产品方案写「允许回退（谈崩重回仲裁不算倒退，**时间轴如实记**）」。
若三态 ＝ 拿 `stage` 的序号和阶段序号比大小，那么 stage 从「已立案」退回「仲裁准备」的那一刻，
「立案」会从 `完成` 翻回 `未到` —— **立案那天确实发生过这件事，这个事实被抹掉了**。
这正是「如实记」的反面，也正是产品方案第贰条骂线性进度条失真的同一个毛病。

→ **三态必须从只追加的事件流推**：某里程碑有达成事件 ＝ 完成（带日期）；
回退 ＝ 再追加一条新事件，旧的完成**不动**。

## 三、提案（最小改动，不新增表）

1. 新增枚举 `CaseMilestone`。**但不是固定五个**——见第 3 条。
2. `TimelineEvent` 加一个可选字段 `milestone?: CaseMilestone`。
   后端在某条事件构成「达成某里程碑」时置上它，其余事件不置。
   **不新增表、不改现有字段语义、不动 `CaseStage`**（它别处还在用）。
3. 案件带一条**有序里程碑轨道** `milestones: CaseMilestone[]`，按该案实际走向排。
   仲裁轨默认五格：`协商 / 仲裁申请 / 立案 / 开庭 / 裁决`。
   **必须可变长**：现有 `CaseStage` 里有 `一审 / 二审 / 执行` 三个值，
   五格轨道根本表达不了它们——案子进了法院，驾驶舱该长出后面的格子，
   而不是永远停在「裁决 完成」。写死 5 会在第一个走到一审的真实案件上当场破功。
4. **三态由前端推，不入契约**：
   - 有 milestone 事件 → `完成`（取该事件 `happenedAt` 作日期）
   - 无事件的里程碑中最靠前的那个 → `进行中`
   - 其余 → `未到`
   - 回退 ＝ 轨道里出现第二条同名 milestone 事件；前端取**最新一条**定位「进行中」，旧的完成保持完成。

```ts
// 提案增量，全文如下，没有别的
export type CaseMilestone =
  | '协商' | '仲裁申请' | '立案' | '开庭' | '裁决'
  | '一审' | '二审' | '执行';

export interface TimelineEvent {
  // …现有字段全部不动…
  /** 置上表示这条事件构成「达成该里程碑」。驾驶舱时间轴只读有此字段的事件。 */
  milestone?: CaseMilestone;
}

export interface CaseRecord {
  // …现有字段全部不动…
  /** 该案的里程碑轨道，有序。仲裁轨默认前五个；进入诉讼后由后端追加。 */
  milestones: CaseMilestone[];
}
```

## 三之二、达成判定表（契约的另一半）

manager 2026-08-28 补充：**哪类事件构成「达成」必须成表写在这张纸上，不许散在后端代码注释里。**

判定口径统一取「**该阶段的收尾动作**」，不取「进入该阶段」——因为「进入」没有可取证的时刻，
而收尾动作**件件有文书**，后端能从已有的证据/文书流里认出来，不需要人工打标。

| 里程碑 | 达成 ＝ 发生了这件事 | 可取证物 |
|---|---|---|
| 协商 | 协商终局：收到单方解除/终止通知，或双方书面确认谈崩，或签署协商解除协议 | 解除通知书 / 协商协议 / 终止谈判的书面往来 |
| 仲裁申请 | 仲裁申请书**递交**至仲裁委（不是写完，是交出去） | 递交凭证 / 收件回执 / EMS 单号 |
| 立案 | 仲裁委出具**受理通知书** | 受理通知书 |
| 开庭 | 庭审**结束** | 开庭笔录 / 庭审记录 / 到庭签到 |
| 裁决 | 收到**裁决书** | 裁决书 |
| 一审 | 收到**一审判决书** | 一审判决书 |
| 二审 | 收到**二审判决书** | 二审判决书 |
| 执行 | 执行终结：款项到账，或法院出具终结本次执行裁定 | 到账凭证 / 执行裁定书 |

**一条通用规则**：某阶段被跳过时，判定不改——例如公司不谈直接解除，
「收到解除通知」照样把「协商」记为达成。**跳过不是没发生，是以另一种方式结束了。**

## 三之三、三态推导（前端做，写在这里是为了两边口径一致）

```
events  = 该案所有带 milestone 的事件，按 happenedAt 升序
last    = events 的最后一条
进行中：
  events 为空                        → 轨道第一格
  last.milestone 在更早事件里出现过    → last.milestone 本身（这是回退信号）
  否则                                → 轨道上 last.milestone 的下一格
                                       （没有下一格 ＝ 全程走完，无进行中）
完成：有达成事件、且不是「进行中」那一格 —— 日期取该里程碑**最早**那条事件
未到：没有达成事件
```

**为什么用「最新事件」而不是「第一个没有事件的格」**：后者在真回退上会算错。
例：撤回仲裁申请退回协商——此时「仲裁申请」「立案」都**确实发生过**，事件不能删（如实记），
按「第一个没事件的格」会把进行中算到「开庭」，而案子其实回到了谈判桌。
按最新事件算，进行中回到「协商」，而「仲裁申请/立案」保持完成带原日期——
**轨道上同时出现「前面进行中、后面已完成」，这不是渲染 bug，这就是回退的诚实样子。**
