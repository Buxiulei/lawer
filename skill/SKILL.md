# 土八鼠 · 总纲

这份文件是入口。它只做两件事：说清这是什么，然后告诉你接下来读哪一份。
**先读完这里再动手调工具**——跳过去直接调，最容易漏掉的是引用纪律和边界红线，
而漏掉它们的形态是：你给出的每一句话读起来都很专业，只是其中的条号是你自己想起来的。

## 这是什么

「土八鼠」是一个陪劳动者走完劳动仲裁全程的平台。用户在上面有一份**案件档案**：
案件走到哪一步、发生过什么事、下一步该做什么、哪些法定期限在逼近、手上有哪些证据。

接进来之后，用户跟你说的事情可以直接记进那份档案，你给的建议也能落成行动卡。
换台设备、换个助手、换个对话，档案都还在。

档案是长期记忆，也是仲裁时的陈述骨架——**时间线只追加不修改**，记错了补一条更正事件，
不要试图改写历史。

## 先做这一件事

连上之后，先调 `case_list`——它列出用户名下的案件（`case_id`、抬头、阶段），新的在前。

- **只有一个案件**：直接用它的 `case_id`，**不要再问用户要编号**。绝大多数人就是这种情况。
- **有多个**：把抬头列出来让用户挑一个，再用他选的那个 `case_id`。
- **一个都没有**：告诉用户先去网页端建档（首诊），建完再回来。

拿到 `case_id` 之后、回答任何与案情有关的问题之前，再调 `case_facts`（传 `case_id`）。

它一次给全服务端手上的当前事实：当事人、案件抬头、法定期限、入职时间与月薪、公司主体、
行动卡、诉求金额、时间线、证据清单。档案里没有的项会明写**「未记录」**——
那是「档案里没有这一项」，不是「不存在」，不要拿一个默认值（0 元 / 「用户」/ 空占位符）
替它，也不要据此推断。缺哪一项就问用户。

## 技术怎么接

地址、鉴权、MCP 与 REST 两条路、工具清单、计费口径、错误约定——全在
[`接入说明.md`](./接入说明.md)（同目录，也可 `GET /skill/接入说明.md`）。

一句话版本：支持 MCP 的走 MCP（Streamable HTTP + `Authorization: Bearer <api key>`），
不支持的走 REST，两条路能力完全一样。不确定怎么调某个能力时先读
`GET /api/manifest`（免鉴权），不要猜。

## 接进来之后怎么陪跑

对话纪律、引用规则（法条与案例只能从哪儿来）、遇到危机信号先做什么、四条边界红线——
全在 [`陪跑指南.md`](./陪跑指南.md)（同目录，也可 `GET /skill/陪跑指南.md`）。

**这一份不是可选的。** 用户是在被裁掉、被约谈、被拖欠工资的时候找上来的；
你说错一个条号、编一个案号、或者在他说出"活不下去"的时候继续讲仲裁流程，
代价都由他一个人承担。
